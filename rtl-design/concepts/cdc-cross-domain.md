# 跨时钟域设计（Clock Domain Crossing, CDC）

跨时钟域（Clock Domain Crossing, CDC）是数字 IC 设计中最具挑战性的问题之一——当信号从一个时钟驱动的同步电路传输到另一个异步时钟驱动的同步电路时，由于两个时钟没有固定的相位和频率关系，目标时钟域的寄存器可能在源信号变化的任意时刻对其进行采样，存在亚稳态（Metastability）风险。现代 SoC（片上系统）通常包含数十到数百个独立时钟域——高性能处理器核、低速外设总线、DDR 存储器接口、SerDes（串行器/解串器）等各自工作在完全不同的频率下——CDC 设计的正确性直接决定了芯片能否可靠工作。CDC 错误在仿真中通常不会复现（仿真器用确定性调度处理时序），但在硅片上以极低概率出现，是最难调试的功能性缺陷之一，因此 CDC 验证（使用 SpyGlass CDC、Mentor Questa CDC 等专用工具）是 ASIC Signoff 的强制检查项。

## 原理

### 亚稳态与 MTBF

当 D 触发器的数据输入 D 在时钟有效沿的建立-保持时间窗口内发生变化时，触发器进入**亚稳态**——输出不是稳定的 0 或 1，而是在 VIL 和 VIH 之间摆动的中间电压，需要一段不定的解析时间（Resolution Time, t_res）才能最终稳定到 0 或 1。在此期间，下游组合逻辑可能将这一不稳定电平解释为不同的逻辑值，导致整个系统进入不确定状态。亚稳态是不可消除的物理现象（由正反馈环路的增益有限性和热噪声决定），CDC 设计的目标不是"消除亚稳态"，而是将亚稳态导致功能错误的概率降低到可接受水平。

**MTBF（Mean Time Between Failures，平均无故障间隔）** 是衡量 CDC 可靠性的核心指标，计算公式为：

$$MTBF = \frac{e^{t_{res}/\tau}}{T_w \cdot f_c \cdot f_d}$$

其中 t_res 是允许的解析时间（通常为一个时钟周期减 t_setup），τ 是触发器的解析时间常数（取决于工艺），T_w 是亚稳态窗口宽度（建立+保持窗口），f_c 是目标时钟频率，f_d 是源数据变化频率。关键洞察：解析时间 t_res 以指数形式影响 MTBF——每增加一个 τ 的解析时间，MTBF 提升约 e ≈ 2.7 倍。这就是多级同步器（级联多个触发器）有效的原因——每级触发器为前级的亚稳态输出提供了额外一个时钟周期的解析时间窗口。单级触发器的 MTBF 可能在几秒量级，加上第二级同步器后 MTBF 可达到数年至数百年，三级同步器则进一步推到上千年的量级。

### 2-FF 同步器

**两级触发器同步器（2-FF Synchronizer）** 是单比特 CDC 信号的经典解决方案：将来自源时钟域的信号经过目标时钟域的两级串联 D-FF 采样后使用。两级同步器不保证消除第一级的亚稳态——它保证第一级的亚稳态在第二级采样前有整整一个时钟周期的解析时间，使第一级输出有极高概率已经稳定。第二级输出是干净的同步信号（可能比源信号延迟 1-2 个目标时钟周期）。实现细节包括：
- 两个触发器必须物理上靠近布局（Netlist 级同步器单元被综合工具标记为 `dont_touch`，防止两级之间的组合逻辑插入）
- 输入信号的翻转率不能高于目标时钟频率——如果单比特信号翻转频率超过 f_target/2，则奈奎斯特条件不满足，2-FF 同步器也无法正确捕获。需要先通过握手协议或异步 FIFO 降频
- 同步器的第一级触发器输出不应用于任何组合逻辑——仅连接第二级触发器的输入，防止不同逻辑路径对亚稳态的不同解析产生不一致

### 格雷码异步 FIFO

多比特 CDC 信号（如数据总线、地址）不能简单地用 2-FF 同步器处理——因为多比特信号的不同比特可能在不同时刻翻转（总线偏斜），使用独立同步器处理可能导致目标时钟域采样到"从未存在的中间值"。多比特 CDC 的核心原理是：**传输状态时保证目标域采样到的比特模式要么全部来自旧值、要么全部来自新值，不允许混合**。具体方案包括：

**格雷码异步 FIFO（Gray-Coded Async FIFO）**：这是多比特 CDC 的通用高效方案，由一个双端口 SRAM/寄存器堆作为数据存储，由读写指针的控制逻辑进行空满判断。FIFO 两端各自运行在自己的时钟域：
- 写时钟域（Write Domain, wclk）：写入数据到 FIFO 存储器，推进写指针（二进制），将写指针转换为格雷码（相邻值仅一位不同）
- 读时钟域（Read Domain, rclk）：从 FIFO 存储器读出数据，推进读指针（二进制），将读指针转换为格雷码
- 关键 CDC 路径：写指针格雷码经过 2-FF 同步器同步到读时钟域 → 读侧比较读指针与同步后的写指针判断空标志（Empty）；读指针格雷码经过 2-FF 同步器同步到写时钟域 → 写侧比较写指针与同步后的读指针判断满标志（Full）

格雷码的关键特性——相邻值仅一位翻转——保证了在任何采样时刻，同步器输出的格雷码要么是旧值、要么是新值，而不会是中间状态（因为中间状态的过渡值会涉及多比特翻转，违反格雷码的单比特变换约束）。从同步后的格雷码再转换为二进制指针，得到保守但正确的空满判断——读侧在写指针"旧一拍"的基础上判断空（可能导致假空——FIFO 中还有数据但报告为空，这是安全侧的保守判断）；写侧在读指针"旧一拍"的基础上判断满（可能导致假满——FIFO 还有空间但报告为满，同样是保守判断）。

### 握手同步器

当数据变化率低、不需要高吞吐率时，**握手同步器（Handshake Synchronizer）** 是一种简便的多比特 CDC 方案：
1. 源时钟域将多比特数据放入保持寄存器，然后翻转一个请求（Req）信号
2. Req 经过 2-FF 同步器同步到目标时钟域
3. 目标时钟域检测到 Req 有效后，锁存数据（此时数据已稳定），然后翻转应答（Ack）信号
4. Ack 经过 2-FF 同步器同步回源时钟域
5. 源时钟域检测到 Ack 有效后，清除 Req，等待 Ack 清除后，准备下一笔传输

完整的 Req→Ack→!Req→!Ack 四相握手保证了数据在传输时的稳定性，数据传输速率受到握手来回的延迟限制——两个 2-FF 同步器的延迟加上跨时钟域的时钟周期，对于低频控制信号（如配置寄存器写入、中断信号）足矣。对于高频数据流，异步 FIFO 是更高效的选择。

### DMUX 同步器与重循环 MUX

**DMUX（Demultiplexer）同步器** 适用于偶尔需传输多比特值的场景（如中断向量、状态标志更新）。数据值先稳定在保持寄存器中，系统状态机将一个单比特"数据有效"toggle 信号通过 2-FF 同步到目标域，目标域检测到 toggle 后从保持寄存器中锁存数据。DMUX 的关键是 toggle 而非电平——电平信号在目标域采样到后不知何时清除，toggle 信号每次翻转即代表一次新数据传输。

**重循环 MUX（Recirculation MUX）同步器** 是 CDC 数据率的另一种方案，数据寄存器内部带反馈 MUX：源侧在数据稳定后翻转 toggle 位，目标侧检测 toggle 后捕获数据。方案的关键是数据保持寄存器的反馈路径确保在目标侧捕获之前数据不被覆盖。

### 复位同步器

全局异步复位释放时必须为每个时钟域独立同步——**复位同步器（Reset Synchronizer）** 对异步复位输入进行两级同步：复位异步生效（直接拉低所有寄存器），释放（Deassertion）经过两个串联 D-FF（不带异步复位引脚，以防复位释放恢复/移除违反）同步到目标时钟上升沿。复位同步器的两级触发器必须复位到 1（rst_n=0 时 Q=0），释放后第一个时钟沿加载 D=1，第二个时钟沿产生干净的同步释放信号。这一设计保证了同一时钟域中所有寄存器的复位释放发生在同一时钟周期，消除了异步复位释放导致的跨时钟域功能错乱（一个周期内部分寄存器已释放、部分尚未释放）。


### 脉冲同步器

当窄脉冲信号（脉冲宽度小于目标时钟周期）需要从快时钟域传输到慢时钟域时，标准的 2-FF 同步器可能因采样窗口错失脉冲而丢失信号。**脉冲同步器（Pulse Synchronizer）** 解决此问题：源时钟域检测到脉冲输入后，通过 toggle 触发器翻转输出——将脉冲宽度展宽为一个持续到下一脉冲的稳态电平——然后此 toggle 信号经 2-FF 同步到目标时钟域，目标时钟域检测到 toggle 信号沿跳变后产生一个目标时钟域宽度的输出脉冲，完成"窄脉冲→展宽→同步→重定时→窄脉冲输出"的 CDC 链。脉冲同步器的输入脉冲速率不可超过目标时钟频率的一半（否则 toggle 信号在两个脉冲之间来不及稳定），且连续两个同向脉冲中间必须至少有一个目标时钟周期的间隔允许 toggle 稳定。

### 多比特 CDC 数据路径的实用策略

实际 SoC 设计中，多比特 CDC 数据路径的策略层次：最高带宽需求（>100MB/s）使用异步 FIFO；中等速率控制和配置数据（1-100MB/s）使用握手同步器；低速率状态更新（<1MB/s）使用 DMUX/重循环 MUX 同步器；极低速配置（单次配置）可以使用门控启动（配置数据稳定后翻转门控 enable 信号使目标域开始工作）。一个常见的设计陷阱是：寄存器配置总线（32 位地址+32 位数据+控制位）直接从处理器域（100MHz）跨到低速外设域（10MHz）——此时格雷码异步 FIFO 的带宽浪费（空满保守导致利用效率可能只有 70%）远大于握手同步器的协议开销（四相握手每个数据字的 8-10 个目标周期），握手同步器是更优选择。


## 关键要点

- 亚稳态不可消除，CDC 设计的目标是通过增加解析时间将 MTBF 推到可接受水平（通常要求 > 1000 年）
- 2-FF 同步器是单比特 CDC 的标准方案——第一级可能进入亚稳态，第二级提供一个完整时钟周期的解析窗口
- 同步器的两级 D-FF 必须物理相邻（无组合逻辑插入），且第一级输出不做任何扇出（仅连第二级输入）
- 多比特 CDC 不可使用独立 2-FF 同步器——总线偏斜会导致目标域采样到"从未存在的过渡值"
- 格雷码异步 FIFO 是 CDC 的大带宽标准方案——读写指针格雷编码确保目标域旧值或新值，空满判断是保守安全的
- 握手同步器适用低速率控制信号：Req∈Ack 四相握手的来回延迟限制了速率上限
- 复位同步器（异步复位 + 同步释放）确保异步复位释放对于每个时钟域是同步的——避免同一时钟域内不同寄存器的释放偏移
- CDC 验证（CDC Lint）是 ASIC Signoff 的强制检查项——SpyGlass CDC、Questa CDC 等工具自动识别未同步的 CDC 路径、缺失同步器、多比特 CDC 等
- 组合逻辑输出不应直接跨时钟域——信号在跨域前应在源时钟域寄存器中拍出，防止组合毛刺被目标域误采
- 从快时钟域到慢时钟域时，源信号必须保持足够长时间（至少目标时钟周期的 1.5 倍）以确保被目标域至少采样到一次
