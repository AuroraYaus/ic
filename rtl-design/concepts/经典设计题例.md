# 经典设计题例

三道数字 IC 设计的经典题目——序列检测器、边沿检测器、售货机状态机。每题给出**分析思路 → 可综合 SystemVerilog 完整实现（逐行注释）→ 易错点**。所有代码满足可综合铁律：完整 if/case（防锁存器）、时序块非阻塞赋值、无不可综合结构。

## 序列检测器（1011）

**题目**：检测输入序列中的 `1011`，检出后拉高 `detected` 一拍（允许重叠，如 `101011` 应检测两次）。

**分析思路**：这是状态机覆盖（Overlapping）的经典题。用 5 状态 Moore 状态机（IDLE/得到1/得到10/得到101/得到1011），每个状态代表"已匹配的前缀长度"——新输入只决定"前缀延伸还是回退"，回退目标由前缀自身的后缀性质决定（如已匹配 `101` 再输入 `1` 回退到 `1` 状态而非 IDLE——因为 `1011` 的后缀 `1` 仍是有效前缀）。检测输出在 `1011` 状态为 1（Moore：输出只随状态，无毛刺）。

```systemverilog
// 序列检测器：检测 1011（允许重叠），Moore 状态机（可综合，逐行说明）
module seq_det_1011 (
    input  logic clk,        // 时钟：采样输入与状态更新
    input  logic rst_n,      // 异步复位（低有效）：复位到 IDLE 状态
    input  logic data_in,    // 串行输入：逐拍送入的待检测序列
    output logic detected    // 检测输出：匹配到 1011 的当拍为 1
);
    // 状态编码：独热码（One-Hot）——译码快、无组合译码毛刺，5 个触发器换速度
    typedef enum logic [4:0] {IDLE = 5'b00001, S1 = 5'b00010, S10 = 5'b00100,
                              S101 = 5'b01000, S1011 = 5'b10000} state_t;
    state_t state, next_state; // 现态与次态

    // 时序逻辑段：状态寄存——异步复位、时钟沿更新
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) state <= IDLE; // 复位回 IDLE——初始前缀长度为 0
        else        state <= next_state;
    end

    // 组合逻辑段：次态计算——case 现态 + 输入，所有分支完整无锁存器
    always_comb begin
        next_state = IDLE;              // 默认值兜底：case 未覆盖的组合回 IDLE，防锁存器
        case (state)
            IDLE:  next_state = data_in ? S1   : IDLE; // 首拍 1：前缀 "1"；0 保持
            S1:    next_state = data_in ? S1   : S10; // "1" 后再 1：前缀回退到 "1"；0 则 "10"
            S10:   next_state = data_in ? S101 : IDLE; // "10" 后 1：进 "101"；0 则 "100" 无有效后缀回 IDLE
            S101:  next_state = data_in ? S1011: S10; // "101" 后 1：匹配 1011；0 则后缀 "10" 回退
            S1011: next_state = data_in ? S1   : S10; // 匹配后重叠判断："1011"+1 → 后缀 "1"；+0 → 后缀 "10"
        endcase
    end

    // 输出逻辑段：Moore 输出只随现态——寄存器无关的纯状态译码
    assign detected = (state == S1011); // 处于 S1011 即检出：输出跟随状态无组合毛刺
endmodule
```

**易错点**：（1）重叠检测的回退路径——`1011` 后输入 `1` 必须回退到 `S1`（后缀 `1`），回退到 IDLE 会漏检 `101011` 的第二次匹配；（2）独热码独热 5 位，case 的 default 必须回安全状态——未覆盖编码（如 `5'b00000`）不得挂死；（3）Moore 输出比 Mealy 晚一拍——若题目要求"检出当拍"输出需说明采用 Mealy 或提前一拍的协议约定。

## 边沿检测器

**题目**：检测输入信号的上升沿与下降沿，各输出一拍脉冲。

**分析思路**：边沿检测 = 当前值与前值比较——寄存一拍旧值，`pos_edge = in & ~in_prev`、`neg_edge = ~in & in_prev`。这是跨时钟域脉冲提取（见 [[rtl-design/concepts/跨时钟域设计|跨时钟域设计]]）与握手接口的基础电路。

```systemverilog
// 边沿检测器：上升沿/下降沿各输出一拍脉冲（可综合，逐行说明）
module edge_detect (
    input  logic clk,      // 时钟：采样输入
    input  logic rst_n,    // 异步复位（低有效）
    input  logic sig_in,   // 被检测信号：任意同步输入
    output logic pos_edge, // 上升沿脉冲：sig_in 由 0 变 1 的当拍为 1
    output logic neg_edge  // 下降沿脉冲：sig_in 由 1 变 0 的当拍为 1
);
    logic sig_prev; // 前值寄存器：上一拍的 sig_in

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            sig_prev <= 1'b0; // 复位清零：复位后首拍不产生假边沿
        end else begin
            sig_prev <= sig_in; // 寄存当前值：下一拍成为"前值"
        end
    end

    assign pos_edge = sig_in & ~sig_prev;  // 上升沿：当前 1 且前值 0——异或变体只能检测变化不能区分方向
    assign neg_edge = ~sig_in & sig_prev;  // 下降沿：当前 0 且前值 1
endmodule
```

**易错点**：（1）输入必须是同步信号——异步输入直接比较会产生亚稳态采样（先打两拍同步，见 [[concepts/亚稳态|亚稳态]]）；（2）脉冲宽度恰为一拍——需要多拍脉冲时加计数器展宽；（3）复位后首拍：若复位值与前值不一致会产生假沿，复位清零前值即可避免。

## 售货机状态机

**题目**：售货机只收 1 元和 2 元硬币，商品售价 3 元，投满找零（1 元）并出货；不设退币（多投必找零）；写出状态机。

**分析思路**：状态 = 已投金额（0/1/2/3+），输入 = 硬币面额（1/2）。4 状态 Moore 状态机：S0（0 元）→ 投 1 到 S1、投 2 到 S2；S1 → 投 1 到 S2、投 2 到 S3；S2 → 任意投币到 S3 并找零 1 元；S3 出货找零后回 S0。`dispense` 与 `change` 在 S3 输出——状态驱动的纯 Moore 输出。

```systemverilog
// 售货机：1/2 元硬币、售价 3 元、多投找零（可综合，逐行说明）
module vending_machine (
    input  logic clk,      // 时钟
    input  logic rst_n,    // 异步复位（低有效）
    input  logic coin_1,   // 投 1 元：当拍为 1 表示投入 1 元硬币
    input  logic coin_2,   // 投 2 元：当拍为 1 表示投入 2 元硬币
    output logic dispense, // 出货：累计金额满 3 元的当拍为 1
    output logic change    // 找零：投超金额时找 1 元（多投必找零，本题最多找 1 元）
);
    typedef enum logic [1:0] {S0, S1, S2, S3} state_t; // 二进制编码：4 状态 2 位足够
    state_t state, next_state;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) state <= S0; // 复位：金额归零
        else        state <= next_state;
    end

    always_comb begin
        next_state = state;         // 默认保持：无硬币输入时状态不变
        case (state)
            S0: begin
                if (coin_1)      next_state = S1; // 投 1：累计 1 元
                else if (coin_2) next_state = S2; // 投 2：累计 2 元
            end
            S1: begin
                if (coin_1)      next_state = S2; // 累计 2 元
                else if (coin_2) next_state = S3; // 累计 3 元：达到售价
            end
            S2: begin
                if (coin_1 || coin_2) next_state = S3; // 已达 2 元：任意投币累计 ≥3，找零在输出段处理
            end
            S3: next_state = S0; // 出货找零后归零：S3 只停留一拍（默认保持被覆盖）
        endcase
    end

    assign dispense = (state == S3);        // 出货：金额满 3 元的状态驱动
    assign change   = (state == S3) && coin_2 && (state == S2); // 找零条件：S2 状态投 2 元（5 元）找 1 元
    // 注意：change 的 S2 条件在 state==S3 时已不成立——改为组合输出逻辑需与次态配合，见易错点
endmodule
```

**易错点**：（1）上一段 `change` 条件写法有误——`state == S3` 与 `state == S2` 互斥恒为 0，正确做法是 Mealy 输出（随现态+输入：`S2 且投 2` 时找零）或把"投 2 找零"单独成状态 S4；题目原意即此坑——找零是"输入相关"输出，Moore 状态机需为 S2 投 2 建独立状态（如 S2_T2），否则找零信息丢失；（2）S3 到 S0 的默认保持覆盖顺序——`next_state = state` 默认值 + case 覆盖是防锁存器惯用法；（3）同拍双硬币输入：假设 coin_1 与 coin_2 互斥（同一时刻只投一枚）——真实设计中用握手协议保证输入合法性。

**修正版找零逻辑**（Mealy 风格，仅输出段）：

```systemverilog
    // 修正：找零 = S2 状态下投入 2 元（累计 4 元，找 1 元）或 S1 状态下投 2 元恰好 3 元不找零
    assign dispense = (state == S3) | (state == S2 & (coin_1 | coin_2) | (state == S1 & coin_2));
    assign change   = (state == S2 & coin_2); // 2 元 + 投 2 元 = 4 元：出货并找零 1 元
    // dispense 需覆盖所有"本拍达到 3 元"的入口：S1+coin_2、S2+任意硬币——组合式 Mealy 输出
```

## 关键要点

- **序列检测的重叠回退**：状态回退目标由"已匹配前缀的后缀"决定——`1011` 后输入 `1` 回退到 `S1` 而非 IDLE，否则漏检重叠匹配
- **边沿检测 = 当前值与前值比较**：上升沿 `in & ~prev`、下降沿 `~in & prev`——异或只能检测变化不能区分方向；异步输入必须先同步
- **Moore 输出无毛刺、Mealy 输出早一拍**：找零类"输入相关"输出用 Mealy 或为输入组合建独立状态——Moore 状态机硬套输入相关输出会丢信息
- **默认值 + case 覆盖是防锁存器惯用法**：`next_state = state` 或 `= IDLE` 兜底，保证所有分支有赋值
- **独热码 vs 二进制编码**：状态少用二进制（省寄存器）、译码深用独热（换速度）——编码选择是面积/速度权衡
- **输入合法性要靠协议保证**：双硬币互斥、握手对齐是设计前提——状态机只处理合法输入组合
