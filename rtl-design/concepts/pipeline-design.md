# 流水线设计（Pipeline Design）

流水线（Pipeline）是提升数字电路吞吐率（Throughput）的核心微架构技术——将一个复杂的组合操作拆分为多个较短的阶段（Stage），相邻阶段之间插入流水线寄存器（Pipeline Register），使多个操作可以在不同阶段重叠执行，如同工厂装配线。流水线的核心权衡是：**吞吐率提升的代价是延迟（Latency）增加**（因寄存器插入的时钟周期开销）和面积/功耗增加（因流水线寄存器的触发器开销）。流水线不仅用于处理器（经典的 5 级 RISC 流水线：取指-译码-执行-访存-写回），也是高性能算术单元（流水线乘法器、浮点加法器）、网络包处理器和图像处理管道的标准设计模式。

## 原理

### 吞吐率与延迟的权衡

理解流水线需要区分两个性能指标：

- **延迟（Latency）**：单个操作从进入流水线到输出结果的总时间。流水线增加了延迟——每个流水线寄存器引入的 t_cq + t_setup 额外开销使总延迟增加，N 级流水线的单操作延迟 = T_comb_original + N × (t_cq + t_setup)。
- **吞吐率（Throughput）**：单位时间内完成的操���数量。流水线提升吞吐率的关键是缩短了关键路径——原组合路径长度 L 被切成 N 段后，每段约 L/N（加上寄存器开销），时钟周期从 T_comb_original 缩短为约 T_comb_original/N，在流水线注满（Fully-Prime）后每个周期可产出一个结果（吞吐率 ≈ f_clk）。

流水线的实际性能取决于流水线的**平衡性**（Stage Balance）——如果某个阶段的关键路径明显长于其他阶段，该阶段成为瓶颈，限制整体时钟频率。理想的流水线各阶段延迟趋近相等。当组合逻辑无法被均匀切分时，有两种选择：接受长延迟阶段的瓶颈周期；或者进一步拆分长阶段使所有阶段平衡（但增加更多流水线级数和寄存器开销）。

### 寄存器切片（Register Slicing）

流水线化的工程实现是**寄存器切片（Register Slicing / Retiming Cut）**——在组合逻辑路径中的适当位置插入寄存器。对于一个纯组合的乘法器（输入 a, b → 输出 p），最简单的流水线切法是在中间位置切断组合逻辑链，插入一级寄存器（Stage 1: 计算部分积阵列 → 寄存器 → Stage 2: 累加部分积 → 输出）。现代综合工具支持**寄存器重时序（Retiming）**优化——在满足功能等价（Functional Equivalence）的前提下自动调整寄存器位置以平衡各阶段延迟，而不需要设计者手工指定寄存器插入位置。Retiming 由 SDC 时序约束驱动，是综合后端进行时序修复（Timing ECO）的重要手段。

从一个周期化的 RTL 描述角度，流水线化的"流水线寄存器切分"等效于在数据路径中插入额外的触发器——Stage N 的输出连接到 Stage N+1 的寄存器输入，下一个时钟周期 Stage N+1 开始使用该数据。简单数据通路（无反馈、无控制耦合）也可以使用 SystemVerilog 的 `always_ff` 移位寄存器风格来描述。

### 停顿与冲刷（Stall & Flush）

流水线的核心复杂性不在于数据直通，而在于**控制**——当流水线需要暂停或清空部分阶段时。

- **停顿（Stall / Bubble Insertion）**：当下一阶段未准备好接收数据时（如后端资源冲突、等待存储器响应、缓存未命中），当前阶段保持输出不变，流水线寄存器保持当前值（通过时钟使能 gate 关断或数据反馈 MUX），在流水线中插入"空泡"。停顿实现的关键是所有阶段的 stall 信号必须是流水线全局一致的（统一 stall 信号或逐级传播 stall 链）。
- **冲刷（Flush / Kill）**：当已进入流水线的指令/操作需要取消时（如分支预测失败、异常中断、复位），将指定阶段的流水线寄存器清零或标记为无效（添加 valid 位，清零 valid 为 0）。Flush 需要精确指定冲刷的起点和范围——冲刷太浅会遗漏需要取消的操作，冲刷太深会不必要地丢弃后续有效操作。

### Valid-Ready 背压握手

流水线阶段之间的数据流控制采用 **Valid-Ready（或 Valid-Accept/Ready-Acknowledge）握手协议**——这是构建弹性流水线（Elastic Pipeline）的基础：

- **Valid**（来自生产者/Parent Stage）：指示当前阶段的数据有效（准备好被消费）
- **Ready**（来自消费者/Child Stage）：指示下游阶段可以接收数据（后级流水线有空位）

数据传输在且仅在 Valid && Ready 同为真的周期发生。Valid && !Ready 时，生产者发生**反压（Backpressure）**——反压从流水线末端逐级向前传播，当末级因输出阻塞拉低 Ready 时，反压逐级传递到流水线入口，最终暂停整个流水线。

Valid-Ready 协议的 RTL 实现是组合逻辑的两个信号相互依赖：Ready 信号通常取决于流水线末级是否空闲以及当前段是否 Valid；Valid 信号的更新逻辑取决于流水线寄存器在传输后是否清空。前向的 Valid 和反向的 Ready 结合在一起产生了组合逻辑环路——**Ready 的计算路径不能包含通过 Valid 的组合反馈**，否则产生组合环路导致综合/仿真失败。实践中，Ready 信号由下游阶段的流水线寄存器状态驱动（不依赖上游 Valid 的组合值），保证了数据流控制的非循环性。

### 数据冒险与转发（Data Hazard & Forwarding）

在流水线中，当后续操作依赖前序操作的结果但前序操作尚未将结果写入寄存器堆时，产生**数据冒险（Data Hazard）**。三类经典数据冒险：

- **RAW（Read After Write，写后读）**：指令 B 需要读取指令 A 的目标寄存器，但 A 的结果尚未写回（结果在流水线中）。通过**转发/旁路（Forwarding / Bypassing）**解决——在 ALU 输入 MUX 前插入多路选择器，将流水线后续阶段的计算结果（在执行/访存阶段的暂存结果）直接转发回 ALU 输入端，跳过写回寄存器的延迟。
- **WAR（Write After Read，读后写）**：指令 B 在指令 A 读取源寄存器之前写入该寄存器。在顺序流水线中不发生（按序写回保证），乱序执行（Out-of-Order）中需要寄存器重命名（Register Renaming）解决。
- **WAW（Write After Write，写后写）**：两条指令写入同一目标寄存器，写回顺序颠倒。同样需要寄存器重命名。

非处理器领域的流水线（算术单元、图像处理器）中，数据冒险同样存在——例如连续的两次乘法，第二次依赖于第一次的结果。此时要么插入 stall 等待第一次结果完成（降低吞吐率），要么设计专用的转发路径将前一次乘法的中间结果直接路由到第二次的输入端口。

### 结构冒险（Structural Hazard）

当两条指令/操作同时竞争同一硬件资源时产生结构冒险。典型场景：单端口存储器——取指和 Load/Store 都需访问同一 SRAM；通用寄存器堆只有一个写端口，同时需要写回两条指令的结果。结构冒险的解决方案包括：增加资源副本（多端口 SRAM、双写端口寄存器堆）、将操作调度到不同周期（插入 stall）、或在架构层面避免同时使用冲突资源（VLIW 编译时调度）。

### 流水线乘法器实例

以 32 位流水线乘法器为例——32 位乘法原组合路径延迟可能在 2-3ns（7nm 工艺），若目标时钟周期为 0.5ns（2GHz），则必须流水线化。Booth radix-4 乘法器可设计为 3 级流水线：
- **Stage 1**：Booth 编码（生成 ±0, ±1, ±2 倍被乘数的部分积，共 16 个部分积）
- **Stage 2**：Wallace 树——将 16 个部分积压缩为 2 个（Sum 和 Carry），通过多级 3:2 CSA（进位保留加法器，Carry-Save Adder）
- **Stage 3**：最终 Carry-Propagate Adder（CPA）——将 Sum 和 Carry 相加得到最终 64 位乘积

每级之间插入流水线寄存器。最终延迟为 3 个周期，但每周期可以启动一个新乘法，稳态吞吐率为每周期 1 个结果。


### 流水线平衡与 Wave Pipelining

流水线级数的确定是吞吐率和延迟的直接权衡选择。实际设计流程中，设计者通过 STA 报告识别最长组合路径，然后将该路径一分为二（插入一级寄存器），重新评估时序——此过程迭代进行直到所有级的关键路径满足目标时钟周期裕量。一种进阶技术是 **C-Slow Retiming**——将原设计的 C 个独立数据流交错到同一流水线中，每个流以原时钟频率的 1/C 速率推进，但流水线总吞吐率保持不变而关键路径同样被 C 倍缩短。

**Wave Pipelining（波流水线）** 是流水线的极限形式——不插入物理寄存器，而是通过精确调整组合路径内部各点信号的到达时间（利用不同逻辑门的延迟差），让多组数据像多个波峰一样在同一组合逻辑云中同时传播而互不干扰。Wave Pipelining 理论上无寄存器开销（零面积/功耗/延迟增量），但对工艺偏差极其敏感——PVT 导致的延迟偏移一旦使不同数据波的透明窗口重叠即产生功能错误，因此仅用于特定时钟周期可调的低敏感度场景，在商业 ASIC 中极为罕见。


## 关键要点

- 流水线将复杂组合操作拆分为多级并行执行，关键是吞吐率提升——代价是延迟、面积和功耗开销
- 流水线寄存器的建立/保持时间开销决定了流水线的最大级数——寄存器开销过大（时钟周期中寄存器占比 > 30%）后继续加流水线级数不再划算
- Valid-Ready 背压握手是弹性流水线的基础——Valid 前向传播，Ready 反向传播，反压从出口逐级传到入口
- 数据冒险（RAW/Hazard）通过转发/旁路解决——将前序操作在流水线中的中间结果直接路由到后序操作的输入端
- 停顿（Stall）和冲刷（Flush）是流水线控制的两大核心操作——Stall 暂停流水线进度，Flush 清空无效操作
- 结构冒险（Structural Hazard）源自硬件资源竞争，通过增加资源副本或调度避免冲突解决
- 寄存器重时序（Retiming）是综合后端自动优化寄存器位置的代数技术——等价变换寄存器边界而不改变功能，可显著改善时序收敛
- 流水线被停顿或冲刷后重新注满（Refill）的周期数等于流水线深度——这是流水线实际吞吐率与理论峰值之间的主要差距来源
- 反压路径的 Ready 信号组合逻辑路径应尽可能短——长 Ready 组合链会成为流水线频率瓶颈，必要时插入 Ready 链的流水线寄存器
- 流水线寄存器不仅为数据提供隔离，也隔离了毛刺——每一级寄存器输出是干净的寄存器输出信号，不会将上游组合逻辑的毛刺传播到下游
