# 编程自测题

RTL 编码能力自测题——每题要求在限定时间内写出可综合的 SystemVerilog 代码。**写作铁律**：完整 if/case（防锁存器）、时序块非阻塞赋值、无不可综合结构（`#` 延迟、initial、$display 等）、复位完整。适用方向：设计（验证方向也需要读懂）。

#### 1. 同步 FIFO（可配置深度与宽度）

**出处**：[[rtl-design/concepts/FIFO设计|FIFO设计]]

**要点**：（1）双端口寄存器阵列（或 memory）+ 读写指针 + 空满标志——同步 FIFO 读写同域，指针直接比较；（2）空：读写指针相等；满：写指针领先读指针一个深度（或计数法：写 +1、读 -1，count==0 空、count==DEPTH 满）；（3）计数法判断直观但多一位比较逻辑——指针法用格雷码或额外状态位区分空满；（4）注意：输出读数据时序（FWFT 首字直通还是寄存输出）——写出哪种说清哪种。

#### 2. 异步 FIFO（跨时钟域、格雷码指针）

**出处**：[[rtl-design/concepts/FIFO设计|FIFO设计]]、[[rtl-design/concepts/跨时钟域设计|跨时钟域设计]]

**要点**：（1）读写指针在各自域生成 → 转格雷码 → 两级同步器同步到对方域 → 再转二进制比较；（2）格雷码空满判断：读空 = 同步后的写指针与读指针全等；写满 = 同步后的读指针与写指针最高两位相反、其余位相等；（3）每个比特位单独同步（格雷码相邻值只差 1 位，同步错误最多指向旧值——保守但安全）；（4）深度必须是 2 的幂——格雷码循环性要求；（5）复位时指针与同步器清零，异步复位置位后先让指针稳定再判空满。

#### 3. 奇数分频器（50% 占空比，如 5 分频）

**出处**：[[rtl-design/concepts/时序逻辑|时序逻辑]]

**要点**：（1）思路：上升沿计数分频波形与下降沿计数分频波形异或——双边沿合成 50% 占空比；（2）两个计数器都在 N-1 翻转（计满回零），上升沿版本在 clk 上升沿翻转、下降沿版本在 clk 下降沿翻转；（3）输出 = 两波形异或（或或）——注意输出是组合逻辑生成，作为时钟要评估毛刺（知识点见 [[rtl-design/concepts/时钟信号使用规范|时钟信号使用规范]]）；（4）进阶说明：说明为什么占空比 50% 需要双边沿、以及单沿解法只能得到 (N-1)/2 : (N+1)/2 的占空比。

#### 4. 格雷码与二进制互转

**出处**：[[rtl-design/concepts/FIFO设计|FIFO设计]]、[[rtl-design/concepts/跨时钟域设计|跨时钟域设计]]

**要点**：（1）二进制 → 格雷码：`gray = bin ^ (bin >> 1)`——一行异或；（2）格雷码 → 二进制：最高位相同，其余位逐位异或累积：`bin[i] = bin[i+1] ^ gray[i]`（循环实现，$N$ 位需要 $N-1$ 级异或——转码延迟 $O(N)$）；（3）格雷码性质：相邻两个码值恰差 1 位——跨域同步时多比特同时翻转的问题降为单比特问题；（4）异步 FIFO 中格雷码指针是"保守判断"——同步后的旧值只会让空满判断偏保守，不会丢数据。

#### 5. 三段式状态机（示例：序列检测或握手控制）

**出处**：[[rtl-design/concepts/有限状态机|有限状态机]]

**要点**：（1）第一段：时序逻辑做状态寄存（现态 → 次态更新）；第二段：组合逻辑算次态（case 状态 + 输入）；第三段：输出逻辑（Moore 输出随状态、Mealy 输出随状态+输入）；（2）第三段用寄存器输出可消除组合毛刺——输出的时序位置清楚；（3）default 兜底未用状态 + 安全状态机（非法状态回 idle）；（4）写完后自查：每个状态在所有输入组合下有定义次态、被赋值信号所有分支有赋值（防锁存器）。

#### 6. valid-ready 握手接口设计（含反压）

**出处**：[[rtl-design/concepts/跨时钟域设计|跨时钟域设计]]、[[rtl-design/concepts/FIFO设计|FIFO设计]]

**要点**：（1）握手规则：valid && ready 同一拍完成传输——ready 可以提前拉高（不等 valid）；（2）数据在 valid && ready 时才采样——发送方在传输完成前必须保持数据稳定；（3）反压实现：接收方 FIFO 将满时拉低 ready——发送方看到 ready=0 保持 valid 与数据等待；（4）易错点：ready 组合逻辑环路（ready 依赖 valid 又影响 valid）——ready 要么寄存、要么与 valid 无关；pipeline 级联时逐级握手。
#### 7. 序列检测器（1011，允许重叠）

**出处**：[[rtl-design/concepts/经典设计题例|经典设计题例]]

**要点**：（1）5 状态 Moore 状态机——状态代表已匹配前缀长度；（2）重叠检测的回退路径：`1011` 后输入 1 回退到 S1（后缀 "1"），回退 IDLE 会漏检 `101011`；（3）输出 `detected = (state == S1011)`——Moore 输出无毛刺但比 Mealy 晚一拍；（4）独热码 + default 兜底安全状态。

#### 8. 边沿检测器

**出处**：[[rtl-design/concepts/经典设计题例|经典设计题例]]、[[rtl-design/concepts/跨时钟域设计|跨时钟域设计]]

**要点**：（1）寄存一拍前值：上升沿 `in & ~prev`、下降沿 `~in & prev`；（2）异步输入必须先经两级同步器——否则采样窗口违例产生亚稳态；（3）脉冲宽度恰一拍，需要更宽脉冲加计数器展宽；（4）复位清零前值，避免复位后首拍假沿。

#### 9. 售货机状态机（1/2 元硬币、3 元售价、找零）

**出处**：[[rtl-design/concepts/经典设计题例|经典设计题例]]

**要点**：（1）状态 = 已投金额（S0/S1/S2/S3）；（2）经典坑：找零是"输入相关"输出——Moore 状态机需为 S2 投 2 元建独立状态，硬套 Moore 会丢失找零信息；（3）正解：Mealy 输出 `change = (state == S2 & coin_2)`、dispense 覆盖所有本拍达到 3 元的入口；（4）输入合法性靠协议保证（硬币互斥）——状态机只处理合法组合。

#### 10. 轮询仲裁（RR）怎么写？公平性怎么保证？

**出处**：[[rtl-design/concepts/仲裁器设计|仲裁器设计]]

**要点**：（1）核心是 one-hot 指针指向"最后授权者"，每轮从 ptr+1 开始环形搜索——刚授权者优先级最低，每轮循环每个活跃请求方恰好授权一次，杜绝饥饿；（2）两段掩码法：`mask_low = (ptr<<1)-1` 拆出高段（严格高于 ptr）与低段（ptr 及其以下——ptr 是低段内最低优先级），两段各自固定优先级、高段优先；低段漏掉 ptr 会导致"唯一请求者是自己"时授权错误为零；（3）固定优先级函数用二补数技巧 `x & (~x+1)` 保留最低位 1；（4）指针更新：授权谁谁成新指针、无请求时保持（空闲不丢轮询状态）；grant 组合输出当拍生效，复位约定 ptr 指向方 0。
