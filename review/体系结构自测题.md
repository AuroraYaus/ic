# 体系结构自测题

体系结构/SoC 岗自测题，覆盖流水线、乱序执行、缓存、总线与 SoC 集成。适用方向标签：设计 / 验证 / 后端 / **架构**。

#### 1. 流水线加速比怎么算？五级流水各阶段干什么？

**适用方向**：架构 · 设计　**出处**：[[architecture/concepts/指令流水线|指令流水线]]、[[rtl-design/concepts/流水线设计|流水线设计]]

**要点**：（1）加速比 $S = \frac{n \cdot k}{k + n - 1}$——任务数 $n$ 足够大时趋近级数 $k$；效率 $E = S / k$；（2）经典五级：取指（IF）→ 译码（ID）→ 执行（EX）→ 访存（MEM）→ 写回（WB）；（3）吞吐率提升的代价是单条指令延迟增加（填充流水线的流水时间）与冒险处理逻辑；（4）实际加速比低于理想值：冒险停顿、各级不平衡、填充/排空开销。

#### 2. 结构冒险、数据冒险、控制冒险分别怎么解决？

**适用方向**：架构　**出处**：[[architecture/concepts/指令流水线|指令流水线]]、[[rtl-design/concepts/流水线设计|流水线设计]]

**要点**：（1）结构冒险：硬件资源冲突（如单端口存储器既取指又读写）——资源复制或分时（哈佛结构指令/数据分离）；（2）数据冒险：RAW（读后写）为主——旁路转发（Forwarding/Bypassing）直接从执行结果传到输入，只剩 load-use 停顿；（3）控制冒险：分支导致取指不确定——分支预测 + 延迟槽或冲刷（Flush）；（4）WAR/WAW 在乱序执行中通过寄存器重命名消除。

#### 3. 乱序执行的核心部件是什么？重排序缓冲（ROB）干什么？

**适用方向**：架构　**出处**：[[architecture/concepts/乱序执行|乱序执行]]

**要点**：（1）乱序执行（Out-of-Order Execution）：指令按数据就绪度而非程序顺序发射——消除与数据无关的停顿；（2）核心部件：重排序缓冲（Reorder Buffer, ROB）按程序序回收结果、提交架构状态——乱序执行、顺序提交；（3）配套：发射队列（Issue Queue）保存待发射指令、物理寄存器堆 + 寄存器重命名消除 WAR/WAW；（4）精确异常依赖顺序提交——ROB 之前的指令全部提交后才能暴露异常。

#### 4. 分支预测分几类？预测错误要付出什么代价？

**适用方向**：架构　**出处**：[[architecture/concepts/分支预测|分支预测]]

**要点**：（1）静态预测：总是跳转/总是不跳转/按分支方向启发式（如向后跳转视为循环跳转）——零硬件成本、精度低；（2）动态预测：1-bit/2-bit 饱和计数器（BHT）、两级自适应（全局/局部历史模式 PHT）、混合预测器、现代 Tournament；（3）配套：分支目标缓冲（BTB）缓存目标地址、返回地址栈（RAS）专预测函数返回；（4）预测错误代价 = 流水线深度 × 周期——冲刷误取指令并重定向，深度越深代价越大，这是现代高性能核预测精度要 >95% 的原因。

#### 5. Cache 三种映射方式？MESI 协议四种状态怎么转换？

**适用方向**：架构　**出处**：[[architecture/concepts/存储层次|存储层次]]、[[architecture/concepts/缓存一致性|缓存一致性]]

**要点**：（1）直接映射：地址决定唯一位置——简单快但冲突缺失多；全相联：任意位置——命中率高但比较器代价大；组相联：折中（主流 8/16 路）；（2）MESI：Modified（已改且独占）→ Exclusive（干净独占）→ Shared（多副本干净）→ Invalid（无效）；（3）写命中 Modified 直接改；读缺失发 BusRd 请求，其他核的 Modified 副本要写回并降为 Shared；（4）MSI/MOESI 是变体（O = Owned 共享脏数据），一致性协议保证所有核看到一致的存储视图。

#### 6. 虚拟内存怎么工作？TLB 是什么？

**适用方向**：架构　**出处**：[[architecture/concepts/存储层次|存储层次]]

**要点**：（1）虚拟地址经页表（Page Table）映射到物理地址——进程隔离、按需调页、内存保护；（2）每次访存都查页表太慢（多级页表要多次访存）——TLB（Translation Lookaside Buffer）是页表项的高速缓存；（3）TLB 未命中：硬件页表遍历（x86）或软件填充（MIPS/RISC-V）——TLB 缺失代价是 Cache 缺失的数倍；（4）Cache 按虚拟还是物理地址索引（VIPT/PIPT）决定 TLB 是否在 Cache 关键路径上——多级 Cache 设计中 L1 常 VIPT、L2+ 用 PIPT。

#### 7. AHB、APB、AXI 三种总线各用在什么场景？

**适用方向**：架构 · 设计 · 验证　**出处**：[[architecture/concepts/片上总线|片上总线]]

**要点**：（1）AHB：单地址流水、一次一传输，适合中速主设备（DMA、Flash 控制器）；（2）APB：无流水、最简单、低功耗，挂外设（UART/SPI/GPIO/Timer）——AHB/APB 桥接；（3）AXI：高性能——地址/数据通道分离、读写独立、outstanding 多事务并行、乱序完成，SoC 主干互联；（4）选型逻辑：带宽需求与面积/功耗代价匹配，慢外设挂 APB、高速内存通路走 AXI。

#### 8. AXI 的通道结构？outstanding 和乱序是怎么实现的？

**适用方向**：架构 · 设计 · 验证　**出处**：[[architecture/concepts/片上总线|片上总线]]

**要点**：（1）5 个独立通道：写地址（AW）/写数据（W）/写响应（B）/读地址（AR）/读数据（R）——分离通道天然支持全双工；（2）握手：VALID/READY 独立互不等待，同时为高才一拍传输——READY 可先于 VALID；（3）outstanding：地址通道不等待前一个事务完成就发下一个地址——事务 ID（AxID）区分不同事务的响应；（4）乱序完成：同一 ID 内顺序、不同 ID 间可乱序——从设备并发处理多个未完成事务，互联（Interconnect）按 ID 路由。

#### 9. DMA 搬运的流程？中断控制器（GIC）怎么处理优先级？

**适用方向**：架构 · 设计　**出处**：[[architecture/concepts/DMA与中断|DMA与中断]]

**要点**：（1）DMA（直接内存访问）让外设不经 CPU 直接搬运数据——CPU 只配置描述符（源/目的/长度）然后处理其他任务；（2）流程：CPU 配置 DMA → DMA 发起总线传输 → 完成中断通知 CPU——搬大数据释放 CPU 带宽；（3）中断控制器集中管理中断源：优先级仲裁、屏蔽、抢占——GIC 分层（分发器 + CPU 接口）支持多核路由；（4）自测常考：DMA 与 Cache 一致性问题（DMA 写内存后 CPU 读到旧 Cache 数据）——需要软件 flush/invalidate 或硬件一致性。

#### 10. DDR 和 PCIe 分别是干什么的？SPI/I2C/UART 呢？

**适用方向**：架构　**出处**：[[architecture/concepts/外设总线协议|外设总线协议]]

**要点**：（1）DDR：处理器主存——双沿采样（DDR 每时钟传 2 次）、突发传输、需训练与刷新，容量与带宽的平衡；（2）PCIe：高速外设互联（SSD/GPU/网卡）——串行差分、分层协议（事务层/数据链路层/物理层）、链路宽度可扩展（x1-x16）；（3）SPI：4 线同步串行（CLK/MOSI/MISO/CS）、全双工、高速简单，Flash/传感器；（4）I2C：2 线（SCL/SDA）、开漏 + 上拉、地址寻址、多主仲裁，低速板级管理；UART：异步串行、无时钟线、波特率对齐，调试与低速通信。

#### 11. RISC 和 CISC 的核心区别？冯·诺依曼和哈佛结构？

**适用方向**：架构　**出处**：[[architecture/concepts/指令集架构基础|指令集架构基础]]

**要点**：（1）RISC：精简定长指令、load/store 架构（只有访存指令碰内存）、寄存器多、易于流水——ARM/RISC-V/MIPS；（2）CISC：复杂变长指令、内存操作数、指令密度高——x86（内部微码翻译成 RISC-like 微操作执行）；（3）冯·诺依曼：指令数据共享存储器与总线——结构简单但有取指/取数冲突（冯·诺依曼瓶颈）；（4）哈佛：指令与数据存储分离、可并行访问——DSP 与嵌入式 MCU 常用，现代 SoC 用 Cache 分离实现"变体哈佛"。

#### 12. SoC 由哪些部分组成？总线互联为什么是性能关键？

**适用方向**：架构 · 后端　**出处**：[[architecture/concepts/SoC架构|SoC架构]]

**要点**：（1）典型组成：CPU 核簇、GPU/NPU、Cache 层级、内存控制器（DDR）、总线互联（NoC/Crossbar）、外设（USB/PCIe/显示）、时钟复位电源管理、调试与安全子系统；（2）互联决定主设备到从设备的延迟与带宽——Crossbar 全交叉（面积换带宽）vs NoC（路由器网络，扩展性好）；（3）SoC 性能瓶颈常在存储通路——多核争抢内存带宽，QoS 仲裁保证实时主设备（显示）不被饿死；（4）自测加分点：结合功耗域规划（UPF）、时钟域规划谈整芯片集成。
#### 13. PCIe 三层结构各管什么？Credit 流量控制和 valid/ready 握手反压有什么区别？

**出处**：[[architecture/concepts/PCIe协议|PCIe协议]]、[[architecture/concepts/外设总线协议|外设总线协议]]

**要点**：（1）事务层管 TLP（地址/数据/完成语义）、数据链路层管可靠传输（序号 + LCRC + ACK/NAK 重传）、物理层管编码与 LTSSM 训练；（2）TLP 跨设备、DLLP 只在相邻两端（ACK/FC 更新/电源管理）；（3）Credit 是预公告式反压：接收方预先公告缓冲容量、发送方持续跟踪额度——无需逐报文确认，与握手式反压的本质区别；（4）Posted（写）可穿透防死锁、Non-Posted（读）须完成回报（Tag 匹配乱序完成）。
#### 14. DDR 为什么需要训练？Write Leveling 和 Read Training 各解决什么问题？

**出处**：[[architecture/concepts/DDR接口与PHY训练|DDR接口与PHY训练]]

**要点**：（1）源同步接口 + 走线偏差使同字节 DQ 到达时间不同——训练用每通道延迟线补偿；（2）Write Leveling 对齐 DQS 与 CK 到 DRAM 的到达（写命令用 CK、写数据用 DQS）；Read Training 分 DQS 门控（前导时刻）与眼图训练（采样点放中心）；（3）ZQ 校准：外接 240Ω 基准 + 片上可编程阵列——上电校准 + 温度漂移周期重校准；（4）时序参数速记：tRCD/tCL/tRP/tRAS/tREFI；训练在每次上电与自刷新唤醒时重跑。
