# ASIC 流程自测题

后端/流程岗自测题，覆盖综合、STA、CTS、布局布线、DFT、功耗与签核。适用方向标签：设计 / 验证 / **后端** / 架构。

#### 1. 逻辑综合的输入输出是什么？面积和速度怎么权衡？

**适用方向**：后端 · 设计　**出处**：[[asic-flow/concepts/逻辑综合|逻辑综合]]

**要点**：（1）输入：RTL + 工艺库（.lib/.db）+ 约束（SDC），输出：门级网表 + 时序/面积报告；（2）三步：翻译（RTL → 通用布尔网络）→ 优化（逻辑化简）→ 映射（绑定工艺库单元）；（3）面积与速度权衡：关键路径用低 Vth/大驱动快速单元，非关键路径用高 Vth/小面积单元——多 Vth 与尺寸混合是面积中性优化的基础；（4）资源共享（互斥运算复用）省面积但加 MUX 级数——综合器在约束驱动下自动取舍。

#### 2. Retiming（重定时）是什么？能解决什么问题？

**适用方向**：后端 · 设计　**出处**：[[asic-flow/concepts/逻辑综合|逻辑综合]]

**要点**：（1）Retiming 把组合逻辑"穿过"寄存器重新分配——移动寄存器位置而不改变外部功能；（2）把慢路径上的逻辑挪一部分到相邻快路径级——平衡各级延迟、拉高 Fmax；（3）数学基础：路径延迟加权重分配，需要初始状态等价处理（穿过寄存器的逻辑影响复位值）；（4）与流水线切分区别：Retiming 不增加寄存器总数（只移动），流水线插入增加寄存器数——两者互补。

#### 3. Setup 和 Hold 检查的方程是什么？Slack 怎么算？

**适用方向**：后端 · 设计　**出处**：[[asic-flow/concepts/静态时序分析|静态时序分析]]

**要点**：（1）Setup：$T_{launch} + T_{clk2q\_max} + T_{comb\_max} + T_{setup} < T_{capture} + T_{period}$——数据必须在一个周期内到达；（2）Hold：$T_{launch} + T_{clk2q\_min} + T_{comb\_min} > T_{capture} + T_{hold}$——新数据不能太快冲掉旧数据（无频率项）；（3）Slack = 要求时间 − 到达时间——正为满足、负为违例；（4）Setup 用最大延迟/最慢角（SS）、Hold 用最小延迟/最快角（FF）——两类检查在不同工艺角签核。

#### 4. 时序违例前端和后端分别怎么修？

**适用方向**：后端 · 设计　**出处**：[[asic-flow/concepts/静态时序分析|静态时序分析]]、[[cross-domain/concepts/时序收敛|时序收敛]]

**要点**：（1）前端（RTL/综合）：流水线切分、逻辑重构、资源共享/复制、Retiming、编码优化、SDC 约束正确性（多周期/伪路径标注）；（2）后端 Setup 侧：LVT 替换、Size-Up、缓冲器插入、有用偏斜（Useful Skew）、布局重排；（3）后端 Hold 侧：延迟单元/缓冲器对、绕行加长走线、HVT 替换、偏斜调整；（4）修复顺序先 Hold 后 Setup——Hold 修好不易被破坏，Setup 修复可能恶化 Hold，ECO 必须全角验证。

#### 5. Fmax 怎么算？时钟偏斜（Skew）对 Setup/Hold 的影响？

**适用方向**：后端　**出处**：[[asic-flow/concepts/静态时序分析|静态时序分析]]

**要点**：（1）$F_{max} = 1 / (T_{clk2q} + T_{comb\_max} + T_{setup} + T_{skew} + T_{jitter})$——关键路径决定上限；（2）正偏斜（捕获时钟晚于发射）帮助 Setup（多出偏斜时间）但伤害 Hold（新数据更快到达）——两者对偏斜的敏感方向相反；（3）CTS 前用理想时钟 + 预估偏斜，CTS 后反标真实偏斜；（4）Useful Skew 主动制造偏斜借时间——必须全角验证不破坏相邻路径。

#### 6. 多周期路径和伪路径分别是什么？约束错了会怎样？

**适用方向**：后端 · 设计　**出处**：[[asic-flow/concepts/静态时序分析|静态时序分析]]

**要点**：（1）多周期路径：设计协议允许数据跨 N 个周期到达（如乘法器后接握手采样）——`set_multicycle_path N -setup`，Hold 检查须移到 N-1 沿（最常见的配置遗漏）；（2）伪路径：物理存在但功能上不可能传输（跨异步域已同步化、测试模式专用路径）——`set_false_path` 免除检查；（3）约束漏设：工具对"假违例"做无效优化——插 buffer 浪费面积甚至引入新问题；（4）约束过宽（真路径设成伪路径）：违例漏检——硅片回来功能错误，是最贵的 bug。

#### 7. 时钟树综合（CTS）的目标是什么？Latency 和 Skew 什么关系？

**适用方向**：后端　**出处**：[[asic-flow/concepts/时钟树综合|时钟树综合]]

**要点**：（1）CTS 从时钟根节点到所有寄存器时钟引脚插入缓冲器树——目标是最小偏斜 + 控制延迟 + 满足 DRV；（2）Latency：时钟源到寄存器的绝对延迟——影响 OCV 累积与跨时钟域约束；Skew：各终点间的相对差——直接影响时序方程；（3）时钟树功耗占动态功耗 30%-40%（活动因子为 1）——CTS 结构决定功耗，时钟门控在 CTS 前插入；（4）时钟网格（Mesh）与 H 树：极低偏斜但功耗/布线代价大，高性能核专用。

#### 8. Floorplan 阶段要做什么？Placement 和 Routing 的关键点？

**适用方向**：后端　**出处**：[[asic-flow/concepts/布局布线|布局布线]]

**要点**：（1）Floorplan：宏单元（SRAM/IP）摆放、IO 位置、电源网络规划、拥塞预判——决定芯片面积与后续一切质量，占时序与拥塞问题的 80%；（2）Placement：标准单元合法化摆放——密度均衡、关键路径缩短、时钟门控组聚集；（3）Routing：全局布线（拥塞驱动）→ 详细布线（DRC 满足）——先进节点双重图形（Double Patterning）与线端规则；（4）时序驱动的物理综合：布局信息反标回综合，迭代收敛。

#### 9. 扫描链的原理？ATPG 和 MBIST 分别测什么？

**适用方向**：后端 · 设计　**出处**：[[asic-flow/concepts/可测试性设计|可测试性设计]]

**要点**：（1）扫描链：寄存器替换为扫描触发器（SFF）串成移位链——测试模式下任意值可移入、内部状态可移出，时序逻辑变成"可控可观测"的组合逻辑；（2）ATPG：自动测试向量生成——对组合逻辑故障模型（固定型故障 Stuck-At Fault）生成最小向量集，覆盖率目标 >95%；（3）MBIST：存储器内建自测试——片上生成 March 算法测试向量自测 SRAM（故障模型与组合逻辑不同）；（4）扫描移位功耗可达功能模式 3-5 倍——分段移位与低功耗 ATPG 控制测试功耗。

#### 10. 功耗三分量（Switching/Internal/Leakage）的来源？静态和动态怎么分？

**适用方向**：后端 · 设计　**出处**：[[asic-flow/concepts/功耗分析|功耗分析]]

**要点**：（1）Switching：负载电容充放电 $\frac{1}{2}\alpha C_L V^2 f$——活动因子、电压平方、频率决定；（2）Internal：短路电流 + 单元内部节点充放电——由输入 slew 与负载决定，先进工艺可超过 switching；（3）Leakage：亚阈值漏电为主 + 栅极隧穿 + 结漏电——无翻转也耗电，待机主导；（4）动态 = switching + internal（翻转相关）、静态 = leakage（与翻转无关）——两者必须分开报告，优化手段完全不同。

#### 11. VCD、SAIF、FSDB 三种活动文件各用在什么场景？

**适用方向**：后端 · 验证　**出处**：[[asic-flow/concepts/功耗分析|功耗分析]]、[[cross-domain/concepts/反标|反标]]

**要点**：（1）VCD：IEEE 1364 标准文本波形——保留每次翻转时间戳，文件巨大（GB 级），用于峰值功耗与时序相关分析；（2）SAIF：只统计翻转次数与 0/1/X 时间占比——MB 级、无时间信息，只能算平均功耗，RTL 早期估算用；（3）FSDB：Synopsys 专有压缩波形——VCD 的 1/10-1/100 体积，门级功耗仿真事实标准；（4）门级签核用 VCD/FSDB（要峰值窗口），RTL 估算用 SAIF——RTL SAIF 驱动门级网表必须做层次映射。

#### 12. 签核（Signoff）检查哪些项？为什么功耗/时序/物理都要签核？

**适用方向**：后端　**出处**：[[asic-flow/concepts/签核|签核]]、[[cross-domain/concepts/时序收敛|时序收敛]]

**要点**：（1）时序签核：全 MCMM 场景 Setup/Hold 清零 + DRV 清零 + SI 分析 + CDC 例外审查；（2）物理签核：DRC/LVS/天线效应（Antenna）/DFM——版图与网表一致且可制造；（3）功耗/IR 签核：功耗热点、IR 压降、电迁移（EM）——供电网络完整性；（4）签核是 Tape-Out 前的"全绿检查表"——任何一项带违例流片都可能致命，多工具交叉验证减少单工具偏差。

#### 13. 后端支持（BES）工程师的主要职责？交付物是什么？

**适用方向**：后端　**出处**：[[asic-flow/concepts/后端支持BES|后端支持BES]]

**要点**：（1）BES（Back End Support）承担综合、DFT、LEC、STA 的流程搭建与执行——RTL 冻结后到网表交付的"中端"环节；（2）核心交付：干净的综合网表 + 约束 + 等价性检查报告 + DFT 向量 + 时序报告；（3）LEC（逻辑等价性检查）保证综合/DFT 修改后的网表与 RTL 功能等价——任何网表改动都要过 LEC；（4）与后端实现（PD）分工：BES 出网表与约束、PD 做版图与签核——ECO 时双向配合。

#### 14. 时序收敛的迭代闭环是什么？ECO 修复的层级？

**适用方向**：后端　**出处**：[[cross-domain/concepts/时序收敛|时序收敛]]

**要点**：（1）综合（WLM 估算）→ 布局（真实位置）→ CTS（真实时钟）→ 布线（真实 RC）——每步 STA 验证，违例决定前进或回退；（2）ECO（工程变更指令）：不改变布局大结构的局部修复——Size-Up/换 Vth/插 Buffer/挪位置；（3）更重的修复：重 CTS、重 Placement——代价递增；（4）收敛标志：所有角所有模式 Slack 全正 + DRV 清零——Slack 从深负到全正的过程就是收敛。
#### 15. JTAG 边界扫描测什么？和内部扫描链有什么区别？

**出处**：[[asic-flow/concepts/可测试性设计|可测试性设计]]

**要点**：（1）层次不同：内部扫描链测芯片内逻辑故障（ATPG 覆盖率），JTAG（IEEE 1149.1）边界扫描测板级互连——焊点开路/短路、芯片间连线；（2）TAP 是 16 状态状态机：TCK/TMS 驱动转移、TDI/TDO 串行数据，TMS 连续 5 拍 1 必回 Test-Logic-Reset；（3）指令 + 数据双寄存器：IR 选寄存器（BYPASS/IDCODE/EXTEST/SAMPLE），DR 移数据；（4）EXTEST 隔离内核、边界单元驱动引脚；附加应用：片上调试、Flash 编程、芯片 ID。
#### 16. LEC 证明什么？为什么综合/DFT/ECO 每步都要过 LEC？

**出处**：[[asic-flow/concepts/逻辑等价性检查|逻辑等价性检查]]、[[asic-flow/concepts/后端支持BES|后端支持BES]]

**要点**：（1）LEC 证明"两个设计在所有输入组合下功能等价"——不证明"设计是对的"（RTL 错了网表忠实复制错误）；（2）比较点 = 触发器 D 端与输出端口——逻辑锥化简后用 SAT/BDD 证明；（3）Setup 状态匹配是第一工程问题：综合重定时/寄存器复制导致状态不匹配，需 Setup 约束声明；（4）DFT 的 LEC 在功能模式验证（扫描使能约束到功能值）；ECO 用增量 LEC 只验证改动锥；网表交付必须附 LEC 通过报告。
