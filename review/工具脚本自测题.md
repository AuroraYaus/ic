# 工具脚本自测题

工具与脚本自测题——覆盖 Makefile 系列与 C 语言（TCL/Perl/Python/Shell/Git 章节待补，见 [[review/复习自测入口|复习自测入口]] 的待补考点清单）。适用方向：设计 / 验证 / 后端（流程脚本为公共技能）。

#### 1. Makefile 中 `=`、`:=`、`?=`、`+=` 四种赋值有什么区别？

**出处**：[[tools/concepts/05-Makefile变量赋值与展开|Makefile变量赋值与展开]]

**要点**：（1）`=` 递归展开——使用时才展开，支持引用后定义变量；（2）`:=` 立即展开——定义时就展开当前值，行为可预期；（3）`?=` 条件赋值——变量未定义才赋值（可用环境变量/命令行覆盖）；（4）`+=` 追加——按原赋值方式追加（递归变量追加递归展开）；（5）工程惯例：优先 `:=` 可预期性，环境注入用 `?=`。

#### 2. wildcard 和 patsubst 函数干什么？写一个"源码列表 → 目标列表"的转换

**出处**：[[tools/concepts/07-Makefile文本变换函数|Makefile文本变换函数]]、[[tools/concepts/08-Makefile路径与文件函数|Makefile路径与文件函数]]

**要点**：（1）wildcard 展开通配符获取真实文件列表（`$(wildcard src/*.v)`）——Make 默认不展开通配符；（2）patsubst 模式替换（`$(patsubst %.v, %.o, $(SRC))`）——批量路径/后缀转换；（3）典型模式：`SRC := $(wildcard src/*.v)` + `OBJ := $(patsubst src/%.v, build/%.o, $(SRC))`；（4）同族函数：notdir/basename/suffix/addprefix——路径拆解组合四件套。

#### 3. 自动依赖（auto-dependency）解决什么问题？怎么生成？

**出处**：[[tools/concepts/14-Makefile依赖与自动生成|Makefile依赖与自动生成]]、[[tools/concepts/15-Makefile高级依赖|Makefile高级依赖]]

**要点**：（1）头文件变化时依赖它的源文件必须重编译——手工维护头文件依赖必然遗漏；（2）编译器生成依赖文件：`gcc -MM` 输出依赖列表，`-include $(OBJ:.o=.d)` 引入；（3）依赖文件本身由编译顺带生成（`-MMD -MP`）——首次构建无 .d 时 `-include` 静默跳过；（4）Make 重启机制保证依赖刚生成后本构重新读取最新依赖。

#### 4. 用 Makefile 搭一个仿真回归流程，要点是什么？

**出处**：[[tools/concepts/21-Makefile仿真回归实战|Makefile仿真回归实战]]

**要点**：（1）目录分层：源文件/编译输出/日志/结果分离——clean 只删生成物不删源码；（2）每个 testcase 一个目标，失败保留日志并继续跑其余 case（不要遇错即停）——回归要"跑完全部再汇总"；（3）用 `-f` 与 `-cmp` 让仿真器自动比对，Makefile 只处理文件依赖与结果收集；（4）结果汇总：pass/fail 计数、失败日志归档——回归脚本的价值在可重复与可诊断。

#### 5. 用 Makefile 组织综合流程，怎么做增量综合？

**出处**：[[tools/concepts/22-Makefile综合流程实战|Makefile综合流程实战]]

**要点**：（1）目标链：RTL → 综合网表 → 报告——每步一个目标、文件时间戳驱动增量；（2）约束（SDC）文件列入依赖——约束变了必须重新综合；（3）工艺库（.db）列入依赖——库版本切换自动触发重跑；（4）综合选项（工具版本、开关）变化无法用时间戳感知——用配置指纹文件（生成 config.stamp）做依赖。

#### 6. Makefile 调试的常用手段？

**出处**：[[tools/concepts/19-Makefile调试与性能|Makefile调试与性能]]、[[tools/concepts/24-Makefile常见错误50例|Makefile常见错误50例]]

**要点**：（1）`make -n` 干跑——只看命令不执行，验证目标与命令；（2）`make -p` 打印全部变量与规则数据库——查变量展开结果；（3）`$(info ...)` / `$(warning ...)` 插桩打印——比 echo 早（展开期即输出）；（4）`--debug=v` 追踪变量、`--debug=i` 追踪隐式规则；（5）常见坑：Tab 与空格混用（配方必须 Tab）、变量名空格、通配符不展开——50 例清单是速查表。

#### 7. 工程上 Makefile 怎么分层？递归 make 和单文件 make 怎么选？

**出处**：[[tools/concepts/18-Makefile递归与大型项目|Makefile递归与大型项目]]、[[tools/concepts/25-Makefile快速参考与版本兼容|Makefile快速参考与版本兼容]]

**要点**：（1）递归 make：每个子目录一个 Makefile，父 make 逐目录调用——模块边界清晰，但失去全局依赖视图（需多次全量解析）；（2）单文件 + include 拆分：一个主 Makefile include 各模块规则文件——全局视图完整、并行安全（make -j）；（3）递归 make 的经典坑：并行时子 make 之间依赖传递需要父级声明依赖（.PHONY 目标串联）；（4）现代 IC 工程倾向"单文件 + include"——工具链目标多但依赖关系全局唯一。

#### 8. 位运算：写一个寄存器置位/清零/翻转/测试的宏四件套

**出处**：[[tools/concepts/C语言在数字IC中的应用|C语言在数字IC中的应用]]

**要点**：（1）置位 `(reg) |= (mask)`、清零 `(reg) &= ~(mask)`、翻转 `(reg) ^= (mask)`、测试 `((reg) & (mask)) == (mask)`；（2）宏参数与整体双重加括号——文本替换在复杂表达式中优先级错乱是经典 bug；（3）位操作一律用无符号类型——`1 << 31` 溢出符号位、移位位数越界都是未定义行为；（4）寄存器访问用掩码宏而非位域——位域布局由实现定义，跨编译器/端序不可移植。

#### 9. 指针与链表：反转单链表（迭代法）怎么写？环检测怎么做？

**出处**：[[tools/concepts/C语言在数字IC中的应用|C语言在数字IC中的应用]]

**要点**：（1）反转用三指针 prev/curr/next——先保存 `next = curr->next` 再反转指针，顺序错则断链；（2）头插需要二级指针（`Node **head`）——传一级指针修改的是副本，调用者看不到变化；（3）环检测用快慢指针——快走两步慢走一步，有环必相遇；无环快指针先到 NULL；（4）复杂度都是 $O(n)$ 时间 $O(1)$ 空间——空间效率是快慢指针相对哈希判重的优势。

#### 10. 宏：多语句宏为什么要 `do { } while (0)`？`#` 和 `##` 干什么？

**出处**：[[tools/concepts/C语言在数字IC中的应用|C语言在数字IC中的应用]]

**要点**：（1）do-while(0) 让宏展开后在 if/else 语境下分号语义正确——否则 `if (cond) MACRO(); else` 的 else 悬空；（2）`#` 参数字符串化（调试信息、错误消息自动带变量名），`##` 记号拼接（批量生成标识符）；（3）宏参数多次求值有副作用陷阱（`MAX(a++, b)`）——有类型检查需求优先 `static inline`；（4）宏是文本替换、无类型检查——能用 inline 就不用函数宏。

#### 11. volatile 与寄存器访问：轮询硬件寄存器为什么不加 volatile 会死循环？

**出处**：[[tools/concepts/C语言在数字IC中的应用|C语言在数字IC中的应用]]

**要点**：（1）编译器按单线程内存模型优化——连续两次读同一地址可能优化成一次，轮询外设寄存器必须 volatile；（2）volatile 语义：每次访问必须真实发生（发起总线读）——禁止寄存器缓存与重排；（3）大小端：小端低字节低地址、大端低字节高地址——跨端序接口必须显式转换，参考模型与 DUT 端序约定不一致是比对失败经典来源；（4）寄存器地址写 `(volatile unsigned int *)0x...` 的转换语法——volatile 修饰的是指针目标不是指针本身。
#### 12. TCL：三种替换（$、[]、{}）有什么区别？foreach_in_collection 是干什么的？

**出处**：[[tools/concepts/TCL脚本实战|TCL脚本实战]]

**要点**：（1）`$` 变量替换、`[]` 命令替换（先执行返回值嵌入）、`{}` 禁止替换——花括号与双引号差异是 TCL 第一课；（2）EDA 工具界面本身就是 TCL 解释器——DC/PT 命令即 TCL 命令；（3）Synopsys 集合对象不能直接字符串化——foreach_in_collection 遍历、get_attribute 取属性；（4）一切皆字符串、条件用花括号、elseif 必须与 } 同行。

#### 13. TCL：综合脚本骨架的组成？search_path 和 link_library 什么区别？

**出处**：[[tools/concepts/TCL脚本实战|TCL脚本实战]]、[[asic-flow/concepts/逻辑综合|逻辑综合]]

**要点**：（1）search_path 是库文件查找目录列表、link_library 是解析网表引用的库（`*` 保留已加载设计）、target_library 是映射目标；（2）流程：read_verilog → read_sdc → link → compile_ultra → report_timing/area → write 网表；（3）路径库名变量化——换工艺库改一行；（4）catch 错误处理 + puts 埋点——脚本失败要留可诊断日志。

#### 14. Python：怎么解析一个大时序报告统计最差 Slack？

**出处**：[[tools/concepts/Python脚本实战|Python脚本实战]]

**要点**：（1）正则命名分组（?P<group>）抓字段行 + defaultdict 聚合 + min 取每组最差；（2）流式逐行读取——GB 级报告不能 read() 全载入；（3）分组取最值是 IC 报告统计的主模式——defaultdict/min/sorted 三件套；（4）__main__ 守卫 + argv 校验 + 明确 exit_code。

#### 15. Python：批量改写 SDC 文件的注意点？

**出处**：[[tools/concepts/Python脚本实战|Python脚本实战]]

**要点**：（1）改文件先备份——SDC 改错使签核失效，备份是最便宜的保险；（2）生成 TCL/SDC 内容时 `[]` `{}` 是普通字符——f-string 原样输出；（3）多周期约束记得 Setup/Hold 配套（N 与 N-1）——漏配 Hold 是经典错误；（4）Python 定位数据面：流程调度留给 Makefile/Shell。

#### 16. Shell：set -euo pipefail 三件套各管什么？

**出处**：[[tools/concepts/Shell脚本实战|Shell脚本实战]]

**要点**：（1）set -e 命令失败立即终止——默认继续执行是静默失败根源；（2）set -u 未定义变量报错——拼写错误当场暴露；（3）pipefail 管道任一环节失败都算失败；（4）流程脚本默认三件套，回归脚本例外——回归要跑完全部再汇总。

#### 17. Shell：仿真回归脚本的骨架要点？

**出处**：[[tools/concepts/Shell脚本实战|Shell脚本实战]]、[[tools/concepts/21-Makefile仿真回归实战|Makefile仿真回归实战]]

**要点**：（1）for 遍历用例 + 计数器汇总 PASS/FAIL；（2）失败日志打标归档（FAIL_ 前缀 + 摘要文件追加）；（3）有失败必须非零退出——上层 Makefile/CI 据此判定；（4）日志三要素：时间戳、工具全量输出、退出码留痕。

#### 18. Perl：-n -p -e 单行处理模式各是什么？$ 和 s/// 默认作用于谁？

**出处**：[[tools/concepts/Perl脚本实战|Perl脚本实战]]

**要点**：（1）-e 执行代码、-n 逐行读入不默认打印、-p 逐行读入并默认打印；（2）$_ 是隐式当前行——/.../ 与 s/// 默认作用于 $_；（3）-pi 原地改写——批量网表改写的存量惯用法，改动前备份；（4）正则语法与 TCL/Python 互通。

#### 19. Perl：维护存量流程脚本的注意点？

**出处**：[[tools/concepts/Perl脚本实战|Perl脚本实战]]

**要点**：（1）Perl 定位存量生态——新脚本用 Python，读懂维护 1990-2010 年代存量脚本是基本功；（2）数值比较 <=> vs 字符串比较 cmp——用错是第一常见维护 bug；（3）use strict/warnings 是新脚本标配，给存量脚本补 strict 先评估兼容性；（4）改正则先备份并抽样验证——正则改错静默漏行比报错更危险。

#### 20. Wavedrom 波形绘制的五条规则是什么？三件套怎么维护？

**出处**：[[tools/concepts/Wavedrom绘制规则|Wavedrom 绘制规则]]

**要点**：（1）WaveJSON 每字符一个时钟周期，所有 lane 长度必须一致才能逐拍对齐；（2）连续同电平必须用 `.` 重复——显式重复（`0000`/`1111`）会在每个周期边界渲染尖刻，只有电平变化才写新字符；（3）data 标签只挂 `2`（低带标签）/`3`（高带标签）——`x` 与 `=` 不渲染标签，`=` 是总线值字符、单比特标志禁用；（4）data 字符后的 `.` 连数据框一起重复——框后先写显式电平字符终止（如 `...20...`）再续 `.`；`.json` 是唯一事实源，改完跑 `tools/render_wavedrom.sh` 重渲染 `.html`/`.svg` 并解码验证电平序列；（5）edge 箭头引用 `node` 字符串的事件字符（非 `.` 字符注册事件点，小写渲染标签、大写隐形）——`A-~>B` 是跳线箭头（起点缺口 + S 曲线越过中间 lane + 箭头），node 缺省时 edge 静默不渲染。
