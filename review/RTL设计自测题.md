# RTL 设计自测题

RTL 设计岗自测题，覆盖亚稳态/CDC、FIFO、状态机、组合逻辑、编码风格与流水线。适用方向标签：**设计** / 验证 / 后端 / 架构。

#### 1. 亚稳态是怎么产生的？两级同步器为什么有效？

**适用方向**：设计 · 验证 · 后端　**出处**：[[concepts/亚稳态|亚稳态]]、[[rtl-design/concepts/跨时钟域设计|跨时钟域设计]]

**要点**：（1）触发器在建立/保持窗口内采样变化的输入，输出进入亚稳态（Metastability）——介于 0/1 之间的中间电平振荡，最终以概率性结果稳定；（2）两级触发器（同步器）给第一级输出留出一个完整周期的解析时间，使失效率从纳秒级降到按 MTBF 计的千年级；（3）同步器只能降概率、不能消除——多比特信号必须配合格雷码或握手协议；（4）同步器两个触发器在版图上要靠近、避免组合逻辑插入。

#### 2. 阻塞赋值和非阻塞赋值的区别？各综合出什么电路？

**适用方向**：设计 · 验证　**出处**：[[rtl-design/concepts/SystemVerilog|SystemVerilog]]、[[rtl-design/concepts/Verilog-HDL|Verilog-HDL]]

**要点**：（1）阻塞赋值（=）立即生效，时序 always 块中描述的是"逐条顺序执行"，可综合出锁存器或组合环路风险；（2）非阻塞赋值（<=）在时间步结束时统一更新，`always @(posedge clk)` 中综合出边沿触发的寄存器；（3）时序块用非阻塞、组合块用阻塞是铁律，混用会导致仿真与综合不一致；（4）阻塞赋值在组合逻辑中"先算后赋值"依赖语句顺序，因此组合块推荐用 `always_comb`。

#### 3. 锁存器和触发器有什么区别？怎么避免锁存器推断？

**适用方向**：设计　**出处**：[[rtl-design/concepts/时序逻辑|时序逻辑]]

**要点**：（1）锁存器电平敏感（使能期间透明）、触发器边沿敏感（时钟沿采样）；（2）组合 always 块中条件不完整（if 缺 else、case 缺 default）会推断出锁存器——综合不报错但时序分析困难、DFT 覆盖率下降；（3）铁律：被赋值的信号在所有控制路径上都必须有赋值；（4）锁存器只有时钟门控 ICG 内部等专用场景才刻意使用。

#### 4. 组合逻辑的毛刺（Glitch）和冒险是什么？怎么消除？

**适用方向**：设计 · 后端　**出处**：[[rtl-design/concepts/组合逻辑|组合逻辑]]、[[concepts/CMOS基础|CMOS基础]]

**要点**：（1）多路径延迟不平衡使输出在稳态前出现短暂错误脉冲——静态冒险（输出本应不变）与动态冒险（本应单次翻转却多次翻转）；（2）根因是相邻质蕴含项切换时缺少冗余覆盖（卡诺图相邻 1 的桥接缺失）；（3）消除手段：冗余项法（$F = AB + \bar{A}C + BC$）、寄存器输出隔离、格雷码编码；（4）同步设计中毛刺不影响功能（时钟沿采样的是稳定值），但增加 20%-30% 动态功耗；毛刺进时钟/复位/使能路径则是功能错误。

#### 5. 同步 FIFO 和异步 FIFO 的空满判断怎么做？为什么用格雷码指针？

**适用方向**：设计 · 验证　**出处**：[[rtl-design/concepts/FIFO设计|FIFO设计]]

**要点**：（1）同步 FIFO 读写同频同相，直接用读写指针差计数判断空满（或指针相等 + 方向位）；（2）异步 FIFO 读写不同时钟域，指针必须同步到对方域再比较——多比特指针直接同步会因同时翻转多位采到错误值；（3）格雷码（Gray Code）相邻值只差 1 位，同步时最多 1 位采样错误（指向旧值或新值），配合两级同步器保证功能正确；（4）满条件：读指针同步到写域后与写指针相差一个深度；空条件：写指针同步到读域后相等。

#### 6. FIFO 反压（Backpressure）的三种策略是什么？水线和在途数据怎么算？

**适用方向**：设计 · 架构　**出处**：[[rtl-design/concepts/FIFO设计|FIFO设计]]、[[architecture/concepts/片上总线|片上总线]]

**要点**：（1）立即反压——下游无缓存、valid/ready 组合直连，ready 拉低当拍停流、无需预留；将满反压——水位到达水线时拉低 ready，预留 ≥ 8 拍（经验值）；整包反压——允许上游发完当前报文（到 EOP），预留 ≥ MAX_LEN（建议 2×MAX_LEN）；（2）水线公式：水位阈值 + 在途数据量 ≤ 深度——反压点与数据源之间 N 级流水，ready 要 N 拍才传导到源头，这 N 拍内源头仍在发送，加上打拍延迟都是在途数据；（3）过度反压是常见错误：多数据流共用读出时"任一通道反压就阻塞全部"，无关数据流被无辜阻塞——反压须按数据类型/通道精确生效；（4）无反压能力的源头（ADC/传感器接口）数据节奏由物理过程决定、无法暂停——只能保证带宽充足或缓冲耗尽时主动丢帧上报。

#### 7. 多比特跨时钟域信号怎么处理？握手协议（四相位）怎么工作？

**适用方向**：设计 · 验证　**出处**：[[rtl-design/concepts/跨时钟域设计|跨时钟域设计]]

**要点**：（1）格雷码编码的连续变化总线（如指针）可配合同步器直接跨域；（2）任意多比特数据不能简单打拍——各比特延迟不一致可能采到中间值；（3）握手协议：发送方置 req → 接收方同步 req 后锁存数据 → 回 ack → 发送方同步 ack 后撤 req，完成一次可靠传输；（4）代价是吞吐率低（多周期一次），适合控制类信号；大数据量用异步 FIFO。

#### 8. 状态机一段式、两段式、三段式各有什么优劣？状态编码怎么选？

**适用方向**：设计　**出处**：[[rtl-design/concepts/有限状态机|有限状态机]]

**要点**：（1）一段式：状态转移、状态寄存、输出全写在一个 always 里——简单但可读性差、综合优化空间小；（2）两段式：时序段做状态寄存 + 组合段做次态与输出——主流；（3）三段式：次态逻辑、状态寄存、输出逻辑分离——输出可寄存器化消除毛刺，最规范；（4）编码：二进制省寄存器、独热码（One-Hot）译码快但寄存器多——速度换面积，安全状态机还需覆盖未用状态。

#### 9. 写一个奇数分频器（50% 占空比），思路是什么？

**适用方向**：设计　**出处**：[[rtl-design/concepts/时序逻辑|时序逻辑]]

**要点**：（1）偶数分频只需计数器翻转输出；奇数分频（如 5 分频）占空比 50% 无法用单一沿实现；（2）标准解法：上升沿计数的分频波形与下降沿计数的分频波形异或（或相或），利用双边沿合成 50% 占空比；（3）计数到 N-1 翻转，两种波形错开半个周期后组合；（4）注意输出经组合逻辑合成，驱动时钟树时要评估毛刺——手写作答时给出完整代码并说明时钟质量权衡。

#### 10. 时钟门控（Clock Gating）怎么实现？为什么不能直接用 AND 门？

**适用方向**：设计 · 后端　**出处**：[[cross-domain/concepts/低功耗设计|低功耗设计]]、[[rtl-design/concepts/时钟信号使用规范|时钟信号使用规范]]

**要点**：（1）AND 门截断时钟：使能信号毛刺会直接传到门控时钟上——时钟路径的毛刺是灾难性的；（2）插入式时钟门控单元（Integrated Clock Gating Cell, ICG）内含电平敏感锁存器：clk 为低时锁存使能、为高时保持——保证门控输出只可能完整跟随时钟、无毛刺；（3）综合工具从 `if (en) q <= d` 风格自动推断 ICG，节省 20%-40% 动态功耗；（4）时钟信号除门控外禁止任何组合逻辑操作（分频/切换都要专用电路）。

#### 11. 流水线怎么提升吞吐率？加速比公式和极限？

**适用方向**：设计 · 架构　**出处**：[[rtl-design/concepts/流水线设计|流水线设计]]

**要点**：（1）流水线把长组合路径切成多级，每级并行处理不同数据——时钟周期由最长一级决定而非整条路径；（2）加速比 $S = \frac{T_{\text{串行}}}{T_{\text{流水线}}} = \frac{n \cdot k}{k + n - 1}$，$n$ 为任务数、$k$ 为级数，$n$ 足够大时趋近 $k$；（3）代价：寄存器开销、面积、延迟（Latency）增加；（4）瓶颈是各级不平衡——最慢一级决定周期，级间平衡是流水线设计核心。

#### 12. casez/casex 和 full_case/parallel_case 有什么坑？

**适用方向**：设计　**出处**：[[rtl-design/concepts/编码风格|编码风格]]、[[rtl-design/concepts/组合逻辑|组合逻辑]]

**要点**：（1）casez 允许 z 位通配（常用于匹配 x/z），casex 连 x 也通配——casex 会把仿真中的不定态 x 当通配匹配，掩盖真实 bug，业界普遍禁用；（2）full_case 告诉工具"所有情况已列全"——但仿真中未匹配输入仍走默认路径，导致仿真与综合不一致；（3）parallel_case 允许重叠匹配（优先级转并行）——但 case 本身是优先级的，标注不当产生功能错误；（4）正解：用 default 兜底 + 唯一性 case（unique case），把意图交给语言本身表达。

#### 13. 异步复位和同步复位怎么选？异步复位同步释放是什么？

**适用方向**：设计 · 后端　**出处**：[[cross-domain/concepts/复位策略|复位策略]]、[[rtl-design/concepts/跨时钟域设计|跨时钟域设计]]

**要点**：（1）异步复位：不依赖时钟立即复位，上电即用，但释放沿与时钟沿竞争可能产生亚稳态；（2）同步复位：时序干净、DFT 友好，但无时钟时无法复位、且增加数据路径逻辑；（3）异步复位同步释放：异步有效 + 同步释放——复位信号经两级触发器同步后释放，同时获得两者优点；（4）现代设计标准答案：异步有效、同步释放，复位树用复位同步器（Reset Synchronizer）统一产生。
#### 14. FIR 滤波器三种结构各有什么特点？怎么省乘法器？

**出处**：[[rtl-design/concepts/DSP算法IP|DSP算法IP]]

**要点**：（1）直接型：移位链 + N 乘法器 + 加法树——直观但加法树深、关键路径长；（2）转置型：输入广播、每级"乘加 + 寄存器"——关键路径与阶数无关，高速标准答案；（3）线性相位系数对称 $h[k] = h[N-1-k]$——先加后乘，乘法器减半；（4）定点协议：中间累加留足位宽，最后一级才舍入。

#### 15. CORDIC 的原理？旋转模式和向量模式区别？第一易错点是什么？

**出处**：[[rtl-design/concepts/DSP算法IP|DSP算法IP]]

**要点**：（1）目标角度分解为 $rctan(2^{-i})$ 预设角度组合，每步只移位加——无乘法器；（2）旋转模式驱动 z 趋 0（算 sin/cos）、向量模式驱动 y 趋 0（算模与相位）——方向符号取剩余角度/负 y 的符号；（3）迭代次数=位宽，可流水可折叠复用；（4）第一易错点：增益因子 $K pprox 1.6467$ 忘记修正。

#### 16. 除法器有哪几种实现？恢复余数法和不恢复余数法区别？

**出处**：[[rtl-design/concepts/DSP算法IP|DSP算法IP]]、[[rtl-design/concepts/算术电路|算术电路]]

**要点**：（1）恢复余数法：不够减商 0 并恢复余数——每步比较 + 两次加减，直观但慢；（2）不恢复余数法：不够减不恢复、下一步改加法——每步一次加减，最常用的定点除法；（3）SRT 高基数：每拍多位商 + 冗余商位（-1/0/+1），CPU 浮点除法核心；（4）牛顿迭代以乘代除：复用乘法器逼近 $1/b$——高性能场景的选择。
