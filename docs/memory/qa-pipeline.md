# 数字IC 问答与知识沉淀流程

用户询问数字IC问题时，遵循以下流程：

0. **问题润色（回答前必做）**：不得直接按原问逐条回答。先提炼核心议题为专业标题，再以议题为中心超越原问边界，覆盖更大知识语境。用户的问题定义入口，不是边界。
1. **检索优先**：先在知识库中搜索是否有相同、相似或相关的问题与解答
2. **命中策略**：
   - 完全一致：累加 `queries` 计数，更新内容
   - 高度相关：在相关文件中扩充章节，插入到邻近位置
   - 部分相关：添加 wikilink 关联
   - 无匹配：创建新概念文件（100+ 行，原理 + 关键要点 + 概念关系）
3. **查询计数**：每个概念文件 frontmatter 维护 `queries` 字段，MOC 底部维护高频查询排名表
4. **文件组织**：相似问题放同一文件相邻位置，不同主题分文件存放
5. **输出标准**：术语标注（中文 English ABBR），图表（Mermaid/Wavedrom），代码（```systemverilog）
6. **终端展示答案**：内容写入文件后，必须在终端向用户展示归纳总结后的答案（润色标题 + 核心原理 + 要点 + 关系），不能只告知"已写入"

**Why:** 用户希望知识库成为可累积、可检索的数字IC学习系统，通过查询频率识别薄弱知识点。终端展示确保即时可读，不用切到 Obsidian 查看。

**How to apply:** 每次收到数字IC问题后，先 grep 搜索知识库，按命中策略处理，更新 frontmatter 的 queries 字段和 MOC 排名表。详见 CLAUDE.md Rule 9。
