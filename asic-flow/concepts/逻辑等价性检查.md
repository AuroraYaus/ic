# 逻辑等价性检查

逻辑等价性检查（Logic Equivalence Checking, LEC）是形式验证的一个分支——用数学方法证明两个设计（通常是 RTL 与综合后的网表、或修改前后的网表）在所有输入组合下功能等价。它与属性检查（Property Checking，见 [[verification/concepts/形式验证|形式验证]]）的区别：属性检查证明"设计满足某属性"，等价性检查证明"两个设计彼此相同"。LEC 在 ASIC 流程中的位置是**网表改动的守门员**：综合、DFT 插入、时钟树调整、ECO 的每一步网表变换都必须通过 LEC 证明"变换没改功能"——任何未经 LEC 验证的网表改动都是流片风险。

## 原理

### 基本流程：配对比较与比较点

LEC 工具（Formality/Conformal）的经典流程分四步：

1. **读入与配对**：读入参考设计（Reference，通常是 RTL 或已验证的网表）与实现设计（Implementation，通常是变换后的网表）；工具按名字/结构把两个设计的模块配对——配不上的点（综合重命名、展平、优化合并）由工具自动映射或人工映射。
2. **比较点（Compare Point）定义**：比较点是两个设计中"必须等价的观测点"——通常是触发器 D 端、模块输出端口。工具不逐门比较，只在比较点处证明两者一致。
3. **逻辑锥化简与证明**：对每个比较点，把驱动它的组合逻辑锥（Logic Cone）抽象成布尔表达式，用 SAT（可满足性求解）/BDD 证明两个表达式对所有输入组合等价——等价证明是 NP 困难问题，但工程实践中的逻辑锥规模可控，工具结合结构相似性加速（两个设计同源时大部分逻辑锥结构相同）。
4. **不通过时的调试**：报告非等价点（Non-Equivalent Point）→ 工具给出反例（Counterexample）输入向量 → 工程师定位是真实功能差异还是工具映射错误（failing point 调试用 schematic 与逻辑锥对比）。

**Setup 阶段的状态匹配**：时序逻辑的等价性要求两个设计的寄存器一一对应（状态匹配）——综合可能重定时、合并/复制寄存器、状态重编码，导致寄存器数量与对应关系变化。工具用 Setup 阶段（建模阶段）分析状态匹配；匹配不上的寄存器（如综合插入的常量寄存器）需要 setup 约束声明——Setup 失败是 LEC 最常见的工程问题。

### 常见变换与等价性类别

ASIC 流程中 LEC 面对的典型变换：

| 变换阶段 | 参考 vs 实现 | 典型差异 |
|:---|:---|:---|
| 逻辑综合 | RTL vs 门级网表 | 资源合并、布尔化简、寄存器重定时/复制 |
| DFT 插入 | 网表 vs 扫描网表 | 触发器换 SFF、插入扫描 MUX——测试模式功能差异需约束屏蔽 |
| 时钟树综合 | 网表 vs CTS 网表 | 插入时钟缓冲器——时钟树单元对功能透明 |
| ECO | 旧网表 vs ECO 后网表 | 局部逻辑改动——只验证改动锥（增量 LEC） |

**等价性类别**：组合等价（同拍输出一致）与时序等价（状态映射后跨拍一致）——重定时后的设计需要时序等价分析（状态序列对应关系平移）。**DFT 的特殊处理**：扫描插入改变了触发器的测试功能——LEC 在功能模式（扫描使能关闭）下验证等价，测试模式由 ATPG 自身的仿真验证覆盖；工具提供 setup 文件把扫描使能约束到功能值。

### 与属性检查的分工

LEC 与属性检查（[[verification/concepts/形式验证|形式验证]]）在流程中互补：LEC 负责"变换保真"（每步网表变换没改功能——全芯片级、全自动、无需激励）；属性检查负责"设计正确"（设计满足协议/属性——模块级、需要编写断言）。工程组合拳：综合/DFT/ECO 后用 LEC 把关、关键模块用属性检查验证协议。LEC 的局限：无法发现 RTL 自身的功能错误（等价性只能证明两个设计"一样"，不证明它们"对"——RTL 错了网表忠实复制错误）——这是 LEC 与功能验证的分工边界。

### 后端支持中的执行位置

在后端支持（BES，见 [[asic-flow/concepts/后端支持BES|后端支持BES]]）的交付链中，LEC 是每个网表版本的强制关卡：RTL → 综合网表（首次 LEC）→ DFT 网表（LEC 确认扫描插入无损功能）→ 每次 ECO 后增量 LEC。交付给物理设计的网表必须附 LEC 通过报告——没有 LEC 报告的网表交付是流程违规。工程惯例：LEC 不通过时禁止进入下一步——"功能等价"是网表变换的唯一合法标准。

## 关键要点

- **LEC 证明"两个设计一样"，不证明"设计是对的"**：RTL 自身的功能错误会被忠实复制到网表——功能正确性由验证保证、变换保真由 LEC 保证
- **比较点 = 触发器 D 端与输出端口**：不逐门比较——逻辑锥化简后用 SAT/BDD 证明等价
- **Setup 状态匹配是 LEC 第一工程问题**：综合重定时/寄存器复制导致状态不匹配——Setup 约束声明是常见动作
- **DFT 的 LEC 在功能模式验证**：扫描使能约束到功能值——测试模式由 ATPG 仿真覆盖
- **ECO 用增量 LEC**：只验证改动逻辑锥——全芯片重跑等价性代价高
- **LEC 是网表交付的守门员**：每个网表版本必须附 LEC 通过报告——不通过禁止进入下一步
