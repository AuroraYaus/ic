# 逻辑综合

逻辑综合（Logic Synthesis）是 ASIC 实现流程的第一个关键阶段，其任务是将寄存器传输级（Register Transfer Level, RTL）的硬件描述代码自动转换为由标准单元库中的门级电路组成的网表（Gate-Level Netlist）。综合过程不是简单的翻译，而是在满足时序、面积和功耗约束的前提下，进行大量优化决策的智能搜索过程。

## 原理

### 三阶段综合流程

现代逻辑综合工具（如 Synopsys Design Compiler、Cadence Genus）的执行过程分为三个主要阶段。第一阶段是 RTL 精化（RTL Elaboration）：综合工具解析 Verilog/SystemVerilog 代码，推断出寄存器、组合逻辑、状态机和存储器等高层结构，生成与工艺无关的通用技术网表（Generic Technology Network, GTECH 或 Generic Netlist）。精化阶段会进行基本的算术优化（如乘法器重构、常数传播）和冗余逻辑消除。

第二阶段是工艺无关优化（Technology-Independent Optimization）：工具在布尔代数层面优化逻辑结构。主要手段包括公共子表达式提取（Common Sub-expression Elimination）、逻辑重构（Logic Restructuring）——利用布尔函数的等价变换减少逻辑级数。例如 `f = ab + ac` 可因式分解为 `f = a(b + c)`，将两级逻辑减少为一级与门加一级或门。此外还有资源共享（Resource Sharing）：互斥操作可以共用同一个运算单元以节省面积。这一阶段的优化不涉及具体工艺库信息，只关注逻辑表达式的简化。

第三阶段是技术映射（Technology Mapping）：工具将优化后的工艺无关网表映射到目标标准单元库的具体门电路上。映射过程使用动态规划或 DAG（Directed Acyclic Graph）覆盖算法，将逻辑树分解为子图并与库中的门单元进行匹配。关键技术包括：分解（Decomposition）将复杂逻辑函数分解为库中已有门的组合；扇出优化插入缓冲器以满足扇出限制；驱动强度选择根据负载电容选择适当的驱动能力。物理感知综合（Physical-Aware Synthesis）进一步引入了布局信息的反馈，在映射阶段就考虑互连线延迟和拥塞，避免了传统综合到布局迭代的反复。

### SDC 约束体系

综合的质量高度依赖于设计约束（Synopsys Design Constraints, SDC）文件的完整性和准确性。核心约束包括：

- 时钟定义（`create_clock`）：指定时钟名称、周期（`-period`）、波形（`-waveform`）和时钟源端口。时钟是整个时序约束体系的根基，所有时序路径都围绕时钟定义展开。
- 输入延迟（`set_input_delay`）：定义外部信号到达输入端口的延迟，代表了芯片外部的时序预算。输入延迟的值来自系统级时序分析，通常由板级 PCB 走线延迟加上上游芯片的时钟到输出（Clock-to-Output）时间组成。
- 输出延迟（`set_output_delay`）：定义输出信号在芯片外部需要的建立时间，代表了接收端对外部信号的时序要求。
- 时钟不确定性（`set_clock_uncertainty`）：为建立/保持时间检查增加余量，涵盖时钟抖动（Jitter）、偏斜（Skew）和额外的设计余量。
- 输入/输出驱动和负载：`set_driving_cell` 和 `set_load` 指定端口的外部驱动能力和负载电容，使工具能计算准确的端口延迟。

### 紧时序与松时序：约束的松紧策略

综合约束的取值策略是决定综合质量（Quality of Results, QoR）的关键决策之一。**紧时序**（Tight Timing，即过约束 Over-Constraint）指施加的时序约束比真实签核目标更严；**松时序**（Loose Timing，即欠约束 Under-Constraint）指施加的约束比真实目标更松。二者的本质区别不在约束的种类，而在约束的"度数"——同样是 `create_clock` 命令，周期取 0.8ns 还是 1.2ns，就决定了该设计是紧综合还是松综合。

**为什么要紧**：综合阶段的时序计算建立在估算之上——线负载模型（Wire Load Model, WLM）对互连延迟的估算误差在深亚微米工艺可达 ±10%-30%，且综合阶段时钟被假定为理想时钟（无偏斜、无抖动）。若综合约束直接取签核目标值，WLM 低估的延迟会在布局布线（Place & Route, P&R）后变成真实的建立时间违例（Setup Violation），此时修复的代价远高于综合阶段。因此业界标准做法是**综合阶段把约束收紧 10%-20%**——目标 1.0ns 的周期，综合时按 0.8-0.9ns 约束，提前支付"误差税"，为 P&R 与时钟树综合（Clock Tree Synthesis, CTS）预留裕量。收紧的具体手段包括：（1）`create_clock -period` 直接收紧时钟周期；（2）`set_clock_uncertainty` 加大建立时间不确定性，把预计的偏斜、抖动与额外设计余量一并计入；（3）输入/输出延迟 `set_input_delay` / `set_output_delay` 取比系统级预算更保守的值；（4）设计规则 `set_max_transition` / `set_max_capacitance` 收紧档位。

**紧的代价与"度"**：过约束不是免费的午餐。约束越紧，优化引擎越激进——在关键路径上换用更大的驱动单元、插入更多缓冲器（Buffer），面积与动态功耗随之膨胀；过度收紧（如 30% 以上——即签核目标周期 1.0ns 却按 0.7ns 综合，等效频率从 1GHz 提高到约 1.43GHz）还会造成缓冲器泛滥，反而加剧 P&R 的布线拥塞（Congestion），使后端更难收敛。约束松紧与面积、功耗构成三角权衡（详见下文"面积与速度的权衡"），业界惯例的 10%-20% 是经验最优区间，具体取值取决于工艺节点（节点越小、互连占比越高、需要预留越多）与后端工具链能力（物理感知综合可少留，见下文"三阶段综合流程"）。

**什么时候应该松**：松约束并非总是坏事，关键在于"松在哪里"。合理的松有两种：（1）**对非关键路径正确放松**——用 `set_false_path` 屏蔽伪路径、用 `set_multicycle_path` 声明多周期路径，这是"该松则松"的正确用法，能把优化资源集中到真实关键路径上；（2）**面积/功耗驱动的设计**——时序不是瓶颈时（如低速控制逻辑），把约束放回真实值或略微放松，让工具对非关键路径执行单元尺寸下调（Down-Sizing）并优先分配高阈值电压（High Threshold Voltage, HVT）单元，回收面积与漏电功耗。危险的松是**欠约束**：对真实关键路径施加比签核更松的约束，或把时钟不确定性设得过度乐观——工具据此判定"时序已满足"而停止优化，违例推迟到签核才集中爆发。此时已到 P&R 后期甚至流片前，工程变更（Engineering Change Order, ECO）的修复代价是综合阶段的数倍。

**分级约束策略（工程实践）**：成熟流程采用"约束逐级放松、精度逐级提高"的递进策略——综合阶段收紧 10%-20%（补偿 WLM 误差）→ P&R 阶段按真实目标或收紧 5% 约束（获得布局信息后精度显著提高）→ 签核阶段用真实目标叠加片上变异（On-Chip Variation, OCV）分析。每一级收紧幅度递减，因为每一级的时序精度递增。松紧结合的正确姿势是**关键路径紧、非关键路径松**：用紧约束压出关键路径的最大潜力，用伪路径/多周期路径释放非关键路径的面积与功耗，两者配合才能同时拿到时序、面积与功耗的最优解。

紧约束的典型 Tcl 脚本（以 1.0ns 签核目标为例）：

```tcl
# ============ 紧约束综合脚本（签核目标 1.0ns，按 0.85ns 收紧 15%） ============

# create_clock：定义时钟 clk，周期取 0.85ns 而非签核目标 1.0ns
# -name clk         —— 时钟名称，后续约束通过此名称引用该时钟
# -period 0.85      —— 周期收紧 15%，提前为 P&R 支付 WLM 误差税
# -waveform {0 0.425} —— 占空比 50%：0 处上升沿、0.425ns（半个周期）处下降沿
create_clock -name clk -period 0.85 -waveform {0 0.425} [get_ports clk]

# set_clock_uncertainty：建立时间不确定性取 80ps
# -setup 0.080      —— 预算构成：CTS 偏斜预留 50ps + PLL 抖动 20ps + 设计余量 10ps
# 紧约束下 uncertainty 应略高于真实预估，把误差也提前吃掉
set_clock_uncertainty -setup 0.080 [get_clocks clk]

# set_input_delay：外部输入延迟取 200ps——比系统级预算的标称值放大 10%
# -clock clk        —— 相对 clk 时钟域计算
# -max 0.200        —— 最迟到达时间：输入数据在时钟沿前 0.2ns 必须稳定
# 输入延迟越大，留给片内逻辑的时间窗口越小，约束越紧
set_input_delay -clock clk -max 0.200 [get_ports data_in]

# set_output_delay：外部输出建立要求取 100ps——同样比标称预算放大 10%
# 输出延迟越大，片内逻辑必须在更早的时刻交出数据，约束越紧
set_output_delay -clock clk -max 0.100 [get_ports data_out]

# set_max_transition：最大信号转换时间取 150ps（约为周期的 15%，属偏严档位）
# 转换时间约束收紧可同时抑制串扰（Crosstalk）并压低动态功耗
set_max_transition 0.150 [current_design]
```

正确的松约束示例（只对"该松的路径"放松）：

```tcl
# ============ 松约束示例：只对非关键路径放松 ============

# set_false_path：屏蔽伪路径——该路径不参与时序检查
# 典型场景：跨时钟域同步器（CDC Synchronizer）的首级触发器——
# 异步输入相对本地时钟无确定相位关系，建立/保持检查本身无意义
# 注意：误屏蔽真实关键路径是签核事故的高发原因，每条 false path 必须逐条评审
set_false_path -from [get_ports async_in] -to [get_pins u_cdc/sync_ff1/D]

# set_multicycle_path：声明多周期路径——每 3 个周期才需要完成一次传输
# -setup 2          —— 建立检查放宽 2 个周期（默认 0，即单周期检查）
# -hold 1           —— 保持检查前移 1 个周期：若不指定 -hold，保持检查停留在
#                      默认边沿，早到数据覆盖中间一拍采集的风险会被漏检（经典陷阱）
# 典型场景：慢速外设寄存器访问、软件可编程配置寄存器
set_multicycle_path -setup 2 -hold 1 -from [get_clocks clk] -to [get_clocks pclk]
```

**与过度约束的边界**：紧约束不等于多多益善。收紧幅度由工艺节点（越小越需多留）、后端工具链能力（物理感知综合引入布局信息后可少留）与设计类型（高速数据通路多留、低速控制逻辑少留）共同决定；引入物理感知综合后 WLM 误差大幅缩小，综合阶段收紧幅度可相应下调到 5%-10%。约束松紧本质上是**时序收敛方法论在综合阶段的具体落地**——紧是为后端预留裕量，松是给优化引擎留出面积与功耗的发挥空间，两者的平衡点就是综合脚本的核心设计参数。

### 优化策略

综合工具的优化引擎可以根据设计目标选择不同的侧重点。时序驱动优化（Timing-Driven Optimization）以建立时间违例（Setup Violation）为第一优先级：工具计算每条路径的到达时间（Arrival Time）与要求时间（Required Time），在违例路径上优先进行逻辑重构、门尺寸调整或插入 buffer。面积驱动优化（Area-Driven Optimization）在时序已满足的前提下，通过门尺寸下调和逻辑合并来最小化总面积。

线负载模型（Wire Load Model, WLM）在物理信息缺失的早期阶段估算互连线延迟。WLM 基于面积统计给出线长与扇出的经验关系，但在深亚微米工艺中，互连线延迟已经超过门延迟，传统 WLM 的误差变得不可接受。为此，现代流程使用物理综合（Physical Synthesis）和拓扑模式（Topographical Mode），在综合阶段引入粗略的布局信息，大幅提升时序估算的准确性。

### Design Compiler 与 Genus 流程实践

Synopsys Design Compiler（DC）是业界最广泛使用的逻辑综合工具，其典型流程通过 Tcl 脚本驱动。标准的 DC 流程分为以下步骤：

1. 设置库和搜索路径：`set target_library` 指定目标标准单元库用于映射，`set link_library` 包含目标库和设计所需的宏单元/IP 库，`set synthetic_library` 包含 DesignWare 组件库。
2. 读入设计：`read_verilog` 或 `read_vhdl` 读入 RTL 源文件，`analyze` 加 `elaborate` 可以精化顶层设计并自动解决层次引用。
3. 施加约束：读入 SDC 文件（`read_sdc`）或通过 Tcl 命令逐条施加约束。典型做法是先施加时钟定义，再施加 I/O 延迟，最后设置面积和功耗目标。
4. 编译与优化：`compile_ultra` 是 DC 最高级别的编译命令，启用 Ultra 优化引擎包括寄存器重定时（Retiming）、高级算术优化、自动门控插入。
5. 输出与报告：`write -format verilog -output design.mapped.v` 输出门级网表，`write_sdc design.sdc` 输出可传递的 SDC，`report_timing`、`report_area`、`report_power` 生成分析报告。

Cadence Genus 的流程与 DC 类似，但使用 `read_hdl` 加 `elaborate` 读入设计，`syn_generic` 执行工艺无关优化，`syn_map` 执行技术映射，`syn_opt` 执行增量优化。Genus 的关键特色是其物理感知综合引擎 iSpatial，可以与 Innovus P&R 紧密集成，通过迭代交换布局信息来提高综合质量。

### 综合质量评估

评估综合结果的质量需要从多个维度审视。时序 QoR（Quality of Results）：最差负余量（Worst Negative Slack, WNS）和总负余量（Total Negative Slack, TNS）应趋近于零。面积利用率：综合面积与库单元面积之比。设计规则违例（DRC）：包括 max_transition、max_capacitance、max_fanout 违例，理想情况下应全部通过。功耗估算：使用工艺库的标称功耗参数和粗略活动数据。门控覆盖率：被门控的寄存器比例。此外还要检查综合前后的逻辑等价性（LEC），确保优化变换没有改变功能。

### 综合 QoR 报告解读

综合完成后，工具以质量报告（Quality of Results Report, QoR Report）的形式汇总全部时序与设计规则检查结果（DC 的 `report_qor` 即输出此表）。读懂 QoR 表是评估综合质量、决定能否进入下一阶段的基本功。以下以一张典型报告为例逐列解读：

| CLKPD(ns) | CLKFrq(MHz) | MaxFrq(MHz) | TarFrq(MHz) | WNS | TNS | Su | WNSLength | LogicLv. | No.Vio |
|-----------|-------------|-------------|-------------|-----|-----|----|-----------|----------|--------|
| 0.39      | 2564.10     | 1721.2      | 1794.87     | -0.191 | -536.115 | 0.00 | 0.651     | 3.000    | 4773.000 |

**逐列含义**：

- **CLKPD（Clock Period，时钟周期）**：综合约束施加的时钟周期，本例 0.39ns。它是"要求"而非"结果"——所有建立时间检查的预算上限。
- **CLKFrq（Clock Frequency，时钟频率）**：约束周期的倒数换算值，$1000/0.39 = 2564.10$ MHz。与 CLKPD 是同一信息的两种表达。
- **MaxFrq（Maximum Frequency，最高可达频率）**：网表当前实际能跑的最高频率，由最差路径决定：$\text{MaxFrq} = 1/(\text{CLKPD} + \text{WNS}) = 1/(0.39+0.191) = 1721.2$ MHz。等价地说，关键路径的真实延迟约为 0.581ns。
- **TarFrq（Target Frequency，目标频率）**：签核目标 1794.87MHz（目标周期 $1000/1794.87 \approx 0.557$ns）。**MaxFrq < TarFrq 说明当前网表连真实目标都达不到**——相对目标仍差约 24ps（$0.557 - 0.581 = -0.024$ns）。
- **WNS（Worst Negative Slack，最差负余量）**：所有路径中最差的建立时间余量 -0.191ns，即最差路径比约束周期多用了 0.191ns。WNS 决定时钟周期需要放松多少才能让最差路径满足要求。
- **TNS（Total Negative Slack，总负余量）**：全部违例路径负余量绝对值之和 -536.115ns，反映违例的"总量"而非"极值"。若 TNS 与 WNS 接近，说明违例集中在少数路径；TNS 远大于 WNS，说明违例面广（本例 4773 条违例、平均每条约 0.112ns，属违例面广的情形）。
- **Su（Setup Uncertainty，建立时间不确定性）**：0.00 表示未通过 `set_clock_uncertainty` 预留偏斜/抖动余量——本例的紧约束完全依靠周期本身收紧实现（各工具的列名缩写可能不同，使用前应核对报告头定义）。Su 不为零时，WNS 会按 Su 的数值进一步恶化。
- **WNSLength（最差路径延迟）**：最差路径的数据路径延迟 0.651ns，包含门延迟与互连延迟、不含发射时钟网络延迟。它比 $\text{CLKPD} + |\text{WNS}| = 0.581$ns 多出的 0.07ns，对应时序计算中捕获时钟偏斜带来的等效收益——该列口径随工具版本而异，使用前应核对报告头定义。
- **LogicLv.（Logic Level，逻辑级数）**：最差路径上的组合逻辑级数 3.000，即发射寄存器到捕获寄存器之间只经过 3 级门。3 级逻辑耗时 0.651ns、平均每级约 0.217ns，说明单元延迟大或互连延迟占比高（工艺节点较旧或驱动单元不足），是值得关注的优化信号。
- **No.Vio（Number of Violations，违例路径数）**：违例时序端点（寄存器 D 引脚与输出端口）总数 4773。与 TNS 组合看：违例面广、平均违例量中等，说明是全局性的单元驱动不足或布局劣化，而非个别极端路径。

**本表的"故事线"**：CLKPD 0.39ns 相对目标周期 0.557ns 恰好收紧约 30%——这是上一节"紧时序与松时序"的典型实例。在收紧约束下工具全力优化，最差路径延迟压到 0.581ns，但相对真实目标仍差 24ps，因此 MaxFrq（1721.2MHz）落在 TarFrq（1794.87MHz）之下。此时若直接进入 P&R，应在时序报告中定位 WNS 路径（`report_timing` 展开），通过逻辑重构、更换更大驱动单元或流水线拆分继续压缩该路径；同时 4773 条违例意味着收紧约束下的优化尚未收敛，需要继续迭代综合或审视 RTL 微架构。

**判定经验**：QoR 合格的粗判标准——（1）MaxFrq ≥ TarFrq（相对真实目标有余量）；（2）WNS/TNS 趋近于零（相对收紧约束）；（3）No.Vio → 0；（4）DRC 类违例（max_transition/max_capacitance）为零。注意 MaxFrq 才是"结果"指标、CLKPD 是"要求"指标——只看 WNS 而不对照 TarFrq，会漏掉"约束已满足但目标仍达不到"的情况（本例 WNS 相对 0.39ns 约束为 -0.191，但真正的问题是对 0.557ns 目标差 24ps）。

### 综合中的增量优化与 ECO

增量综合（Incremental Synthesis）在初始综合结果基础上进行局部优化而不重跑完整流程。典型场景包括：修复特定路径的 DRC 违例、轻微时序违例（WNS > -50ps）的缓冲器插入或门尺寸调整、以及局部功耗优化。增量综合命令（`compile_ultra -incremental` 在 DC 中或 `syn_opt` 在 Genus 中）在已有网表上运行，仅对违例区域进行局部重综合，保留非违例部分的优化成果。

**重定时**（Retiming）是综合中最强大但也最危险的优化技术——工具将寄存器沿着组合逻辑路径向前或向后移动，将长路径的延迟"借给"短路径，在不改变周期数的前提下均衡路径延迟。重定时可以显著改善 WNS（改善幅度可达 20%-40%），但改变了所有寄存器位置——综合后的 LEC 必须使用支持重定时的 SEQ 模式而非默认的 COM 模式，否则所有寄存器比较点都会因为位置改变而报告假不匹配。

### 综合中的有限状态机优化

综合工具对有限状态机（Finite State Machine, FSM）执行专门的优化变换。**状态编码优化**（State Encoding Optimization）根据状态数量和转移复杂度选择最优编码方式——二进制编码（面积最小但解码复杂）、独热码（One-Hot, 速度最快但寄存器开销大，适合 ≤32 状态）、格雷码（Gray Code, 相邻状态仅变化 1 位，功耗最低）。**安全状态恢复**（Safe State Recovery）在综合中插入额外逻辑使 FSM 在未使用状态的编码被单粒子翻转（SEU）触发时能自动回到有效状态——这对于航空航天和汽车电子设计是强制性要求。综合工具还可以自动将显式风格和隐式风格的 RTL 描述统一优化为最优的门级 FSM 实现。

### 层次化综合与模块边界优化

大规模 SoC 设计中通常采用层次化综合（Hierarchical Synthesis）策略——将顶层芯片分为多个模块，每个模块独立综合后再在顶层集成。层次化综合的核心挑战是**边界优化（Boundary Optimization）**——模块端口（Interface Ports）的时序约束必须在综合阶段正确设置，否则模块集成后会在跨边界时序路径上出现大量违例。DC 的 `compile_ultra -gate_clock` 和 Genus 的 `syn_opt -boundary_optimization` 可在综合时推断模块端口的驱动和负载条件，对跨模块的关键路径执行逻辑重构（如复制的组合逻辑下沉到下游模块的输入端）。**接口逻辑模型**（Interface Logic Model, ILM）是层次化综合中的关键抽象——模块综合完成后生成包含端口时序弧和寄存器的精简模型，上层集成和顶层 STA 使用 ILM 而非完整网表，在保证时序精度的前提下减少 80% 的计算量。

### 面积与速度的权衡

面积（Area）和速度（Speed / Performance）是数字 IC 设计中最经典的二律背反，综合工具的优化引擎本质上在两者的 Pareto 前沿上寻找给定约束下的最优解。

**对立的根源**：速度提升需要并行化——更多的计算资源（更多的加法器而非分时复用、更宽的 MUX、更深的流水线），这些资源消耗面积。面积缩减需要串行化——资源和分时复用，但每个操作的串行执行降低了吞吐率。

**常见权衡场景与实战案例**：

1. **流水线深度 vs 面积**：5 级流水的 32 位乘法器吞吐率为每周期 1 次，面积约 15,000 等效门（含 5 级寄存器）。非流水线版本面积约 10,000 等效门（减少 5 级寄存器），但吞吐率仅每 5 周期 1 次。流水线版本面积增大了约 50%，吞吐率提升 5 倍——面积-速度比（Area-Delay Product）改善了约 3.3 倍（因为 15000/10000 × 1/5 = 0.3，即每单位吞吐率的面积成本降低了 70%）。

2. **资源复制 vs 串行化**：一个 64 位数据通路需要对两个独立的 64 位操作数同时执行加法——用两个 64 位加法器（2x 面积，1 周期完成）或用一个 64 位加法器分两拍串行执行（1x 面积，2 周期完成）。选择取决于吞吐率目标和面积预算。

3. **独热编码 vs 二进制编码的 FSM**：16 状态的 FSM——独热编码（16FF + 简单次态逻辑，面积约 2x 但速度约快 30%-40%）vs 二进制编码（4FF + 复杂译码器，面积约 1x 但速度约慢 2x-3x）。高速接口控制器选独热，低速配置 FSM 选二进制。

4. **超前加法器 vs 行波加法器**：64 位加法——并行前缀加法器（Kogge-Stone/Brent-Kung，面积约 3x-4x 行波加法器，延迟约 O(log N) vs O(N)）。CPU ALU 用并行前缀（速度第一），IoT MCU ALU 用行波进位（面积第一）。

**面积-速度乘积（Area-Delay Product）**：经典的数字电路效率指标。$\text{ADP} = \text{Area} \times \text{Delay}$。两个实现方案的 ADP 之比衡量了综合效率的优劣——ADP 越小的方案在给定约束下越优。但实际项目中 ADP 不直接作为优化目标，因为面积和延迟通常不可互换——时序违例不是"多用面积就能买回来"的线性关系。

**综合工具如何做权衡**：综合工具使用带权重的代价函数（Cost Function）：
- 时序驱动综合（Timing-Driven Synthesis）：代价函数 = $\sum w_i \times \max(0, T_{required} - T_{arrival})$，先将所有违例路径的负裕量加权求和，在此前提下最小化面积。逻辑：先满足速度约束，再节流面积。
- 面积驱动综合（Area-Driven Synthesis）：当时序约束已全部满足（WNS >= 0），工具执行门尺寸下调（Down-Sizing）——将关键路径上的大驱动单元替换为同功能的小驱动版本，从非关键路径回收面积。逻辑：在速度达标的前提下，能省就省。
- 多目标优化：使用拉格朗日松弛法或帕累托搜索在面积-速度-功耗三维空间中寻找最优权衡面。

**其他设计权衡维度**：除面积-速度外，数字设计中还存在**速度-功耗**（高频设计功耗大）、**面积-功耗**（大芯片漏电高）、**可测性-面积**（扫描链增加 MUX 面积）、**可靠性-面积**（TMR 面积 3x+）、**设计周期-芯片品质**（缩短周期 vs 优化收敛）等多元权衡关系。

**能否同时提高速度又减小面积？** 理论上不可兼得（面积-速度的 Pareto 前沿是单调的），但在以下特定场景下可以实现"双赢"：(a) 初始设计中有冗余逻辑——通过资源共享消除冗余，同时提升速度（减少 MUX 延迟）和减小面积；(b) 使用更好的微架构——例如用 Wallace 树代替行波阵列乘法器，Wallace 树既比行波阵列快（O(log N) vs O(N)）又可能在面积上更优（Wallace 树减少中间进位存储 DFF）；(c) 综合约束过度保守——将过度约束的裕量释放后，工具可以用更小的门满足真实约束，面积自然缩减。

### 资源共享（Resource Sharing）

资源共享（Resource Sharing）是逻辑综合中通过**时分复用**硬件运算单元来减少面积的技术。其核心思想：当多个操作**不会同时执行**时（互斥操作），它们可以共用同一个运算单元，通过 MUX 选择不同的输入操作数。

**基本原理**：考虑以下 RTL：

```systemverilog
always_comb begin
    if (sel == ADD)  result = a + b;
    else             result = c + d;  // 两个加法互斥
end
```

综合工具识别到 `a+b` 和 `c+d` 不会同时计算——因为它们在互斥的 if-else 分支中。工具将两个加法器合并为一个，在输入端插入 MUX 选择操作数对 `(a,b)` 或 `(c,d)`，输出端直接使用加法器的和。面积从 2 个加法器减少到 1 个加法器 + 2 个 MUX（MUX 面积远小于加法器——32 位加法器约 300-500 门，32 位 2:1 MUX 约 100-150 门），总节省约 40%。

**共享的约束条件**：(a) 操作必须**互斥**——综合工具通过控制/数据流分析判定两个操作是否可能在同一周期同时执行；(b) 运算类型必须**相同或兼容**——只能共享同类型的运算单元（两个加法器可以共享，加法器和乘法器不能共享——除非使用更通用的 ALU）；(c) 操作数位宽相同或可对齐。

**综合工具的实现**：DC 的 `compile_ultra` 和 Genus 的 `syn_opt` 会自动执行资源共享——这是工艺无关优化阶段的一个重要变换。工具构建数据流图（Data Flow Graph, DFG），识别互斥操作节点，将可共享的节点合并。设计者可通过约束控制共享粒度：`set_resource_allocation` 或 `set_dont_share` 来覆盖自动决策。

**资源共享 vs 流水线的互补**：资源共享减少面积但降低吞吐率（因为互斥操作串行化）；流水线增加面积但提升吞吐率（因为操作并行重叠）。在设计中：吞吐率要求低的配置和初始化路径使用资源共享节省面积；数据通路的高速路径使用独立运算单元 + 流水线保证吞吐率。两者在同一设计中互补共存。

**过度共享的潜在问题**：(a) MUX 延迟——共享单元输入端增加的 MUX 引入了额外的组合延迟，可能使原本能通过时序的路径变成关键路径；(b) 布线拥塞——共享单元扇入大量 MUX 导致局部布线密度激增，可能增加物理设计的拥塞；(c) 可测性——共享单元的内部故障传播更复杂，ATPG 工具可能需要更多测试向量来覆盖所有共享路径。

### Retiming 的原理与优化效果

Retiming（寄存器重定时 / 寄存器重分布）是综合工具通过**沿组合逻辑路径移动寄存器**来优化时序的数学变换，在不改变设计功能（周期数层面的 I/O 行为）的前提下重新均衡各流水线级的延迟。

**核心原理**：将寄存器沿着组合逻辑路径向前（Forward Retiming，从输入侧向输出侧移动）或向后（Backward Retiming，从输出侧向输入侧移动）移动。从寄存器出发的每条输入/输出路径上，移动操作会从该路径的组合逻辑中"减去"或"增加"一段逻辑——本质上是从长路径"借"逻辑给短路径，实现各路径延迟的均衡。

**数学描述**：给定一个同步电路图 $G = (V, E)$，每个顶点 $v$ 有一个组合逻辑延迟 $d(v)$，每条边 $e$ 有 $w(e)$ 个寄存器。Retiming 是一个整数标签函数 $r: V \to \mathbb{Z}$，重定时后边 $e: u \to v$ 上的寄存器数变为 $w'(e) = w(e) + r(v) - r(u)$，且所有边保持 $w'(e) \ge 0$。最优 retiming 问题可在多项式时间（$O(|V|^3 \log |V|)$）内用 Leiserson-Saxe 算法求解最小时钟周期。

**优化效果**：

1. **时钟周期优化**：最直接的效果。例如，流水线中有两级：第一级组合延迟 2.0ns，第二级 0.5ns，时钟周期受限于第一级的 2.0ns。Retiming 将第一级的部分逻辑"搬"到第二级——两级均衡后各约 1.25ns，时钟周期从 2.0ns 改善到 1.25ns（提升 37.5%）。改善幅度可达 20%-40% 的 WNS 修复。

2. **面积中性的时序优化**：Retiming 不增加也不减少寄存器总数——仅重新分配已有寄存器在各边上的分布。相比缓冲器插入（增加面积）和门尺寸调整（增加面积和漏电），retiming 是"纯时光优化"——不消耗额外面积。

3. **消除过约束路径**：时序过约束（Over-Constrained）路径在 retiming 后获得更多逻辑深度分担，可能将原本需要大驱动单元的关键路径松弛回中速单元可满足的范围，间接降低面积和功耗。

**Retiming 的风险与约束**：

- **LEC 模式切换**：Retiming 改变了所有寄存器的位置和名称——综合前（RTL）和综合后（Gate）的寄存器不再一一对应。标准的组合等价性检查（COM mode LEC）会报告所有寄存器比较点不匹配（假违例）。必须使用**时序等价性检查（SEQ mode LEC）**——SEQ 模式不是逐点比较寄存器，而是证明重定时前后两个电路在所有可达状态序列上的输出序列完全一致。SEQ LEC 比 COM LEC 慢一个数量级且复杂得多，需要在项目计划中预留额外验证时间。

- **初始状态不可移植**：RTL 中为每个寄存器显式指定的复位值在 retiming 后无法直接映射——因为寄存器被移动了，原寄存器的复位值对应的逻辑位置可能发生了变化。Retiming 后必须重新验证所有可观测点的上电初始值和复位后的首个有效输出。对于有严格上电时序要求的模块（如带状态机的总线控制器），retiming 可能导致上电后的首个状态转换不确定——需要额外约束禁止在状态寄存器所在路径上执行 retiming。

- **与 DFT 的交互**：扫描链替换（Scan Replacement）在综合之后执行，将功能 DFF 替换为扫描 DFF。Retiming 改变了功能 DFF 的位置和数量（向前移动 N 位 = N 个额外 DFF 被添加到输出端），导致预期扫描链长度与实际不匹配。标准做法：在 DFT 插入步骤**之前**完成 retiming——综合阶段 retiming，DFT 阶段在 retiming 后的网表上插入扫描链。DC 的 `compile_ultra -retime` 与 `insert_dft` 的命令顺序是关键。

- **物理信息依赖性**：Retiming 在综合阶段缺乏物理布局信息——均衡延迟基于线负载模型（WLM）的估算而非真实 RC 反标。工艺 < 28nm 后互连延迟与门延迟可比，WLM 精度不足以支撑激进 retiming。解决方案：在 P&R 的详细布局后基于实际 RC 再执行一次物理重定时（Physical Retiming / Re-Pipelining），确保移动后各级延迟真实均衡。

## 关键要点

- **综合三阶段缺一不可**：综合三阶段：RTL 精化（推断高层结构）到工艺无关优化（布尔级逻辑简化）到技术映射（映射到标准单元库的门级网表），三个阶段缺一不可
- **时钟定义是 ASIC 流程第一因**：`create_clock` 和 `create_generated_clock` 是时序约束的根基，时钟定义错误会导致整个综合结果无效，是 ASIC 流程中的第一因
- **先达标再节流的优化逻辑**：时序驱动优化（Timing-Driven）以建立时间违例修复为首要目标，面积驱动优化（Area-Driven）在时序闭合后再压缩面积，两者是先达标再节流的逻辑
- **综合紧约束 10%-20% 是业界标准**：综合阶段把约束收紧 10%-20%，提前补偿 WLM 估算误差（±10%-30%）并为 P&R/CTS 预留裕量；收紧幅度由工艺节点、后端能力与设计类型共同决定
- **过度收紧适得其反**：过度收紧（30% 以上）触发缓冲器泛滥——面积与动态功耗膨胀，同时加剧 P&R 布线拥塞，使后端更难收敛
- **该松则松是正确姿势**：`set_false_path` 与 `set_multicycle_path` 对非关键路径的放松是"合法的松"，能把优化资源集中到真实关键路径；欠约束则让违例推迟到签核才爆发，ECO 修复代价倍增
- **MaxFrq 是结果、CLKPD 是要求**：读 QoR 报告先对照 MaxFrq 与 TarFrq——WNS 相对的是收紧约束，MaxFrq < TarFrq 才是真实目标未达成的信号（$1/(\text{CLKPD}+\text{WNS})$ 即当前最高可达频率）
- **物理感知综合减少时序迭代**：物理感知综合（Physical-Aware Synthesis）将布局信息反馈到综合阶段，大幅减少了传统流程中综合与布局之间的时序迭代；拓扑模式（Topographical Mode）可使时序估算精度从 ±30% 提升至 ±10%
- **`check_timing` 应在综合前强制执行**：约束完整性检查（`check_timing`）应在综合前强制执行，发现未约束的路径、不合理的多周期约束或缺失的时钟定义
- **综合输出四大产物**：综合输出包括门级网表（Verilog）、SDC 文件（可传递到下游工具）、延迟信息（SDF 或工具数据库）和设计约束报告
- **门控时钟节省 20%-40% 动态功耗**：门控时钟（Clock Gating）的插入通常由综合工具自动完成（通过 `set_clock_gating_style` 指令），能节省 20%-40% 的动态功耗；最小门控位宽参数（通常 3-4 位）是门控插入的灵敏度调节——低于此位宽的寄存器组不值得插入独立的 ICG
- **`set_dont_touch` 保护关键路径**：综合中的 `set_dont_touch` 属性保护关键路径和手工设计的电路不被工具意外修改，必须谨慎使用
- **`compile_ultra` 和 `syn_opt` 是最高级综合命令**：Design Compiler 的 `compile_ultra` 和 Genus 的 `syn_opt` 是最高级别的综合命令，启用了物理感知、寄存器重定时和高级算术优化
- **LEC 是质量验证第一关**：综合后的形式等价检查（RTL vs Gate LEC）是质量验证的第一关，需要确认布尔级优化没有改变设计的功能语义；寄存器重定时后必须使用 LEC 的 SEQ 模式而非默认 COM 模式
- **乘法器选择影响时序和面积**：算术优化（Arithmetic Optimization）将 RTL 中的 `+`, `*` 等运算符映射到 DesignWare 数据通路组件，乘法器的选择（Wallace Tree, Booth, 流水线级数）对时序和面积有决定性影响
- **综合预留 DFT 时序裕度**：综合阶段必须为测试逻辑（如扫描链 MUX）留出时序裕度，扫描 MUX 增加功能路径延迟约 10-30ps（28nm 工艺），在综合的时序预算中需要预先计入
- **边界优化是层次化综合关键**：层次化综合（Hierarchical Synthesis）中边界优化是关键，模块端口的时序约束偏差是跨模块路径违例的主要根源
- **ILM 减少 80% 计算量**：接口逻辑模型（ILM）是层次化综合中的关键抽象，在保持时序精度的同时减少 80% 的计算量
- **FSM 编码方式各有侧重**：FSM 优化中独热码（One-Hot）速度最快但寄存器开销大；格雷码功耗最低；二进制编码面积最小，综合工具根据状态数和时序约束自动选择

## 与其他概念的关系

- [[asic-flow/concepts/静态时序分析|静态时序分析（STA）]] — 综合后的网表需要通过 STA 验证时序，SDC 约束在综合和 STA 中共享；综合阶段的线负载模型（WLM）精度有限——STA 在获得反标寄生参数后可精确评估综合与最终时序之间的偏差
- [[cross-domain/concepts/时序收敛|时序收敛（Timing Closure）]] — 约束松紧策略是时序收敛方法论在综合阶段的具体落地：紧约束预留跨阶段裕量，伪路径/多周期路径正确收缩检查空间，"逐级放松、精度逐级提高"的约束递进本身就是时序收敛的主线
- [[asic-flow/concepts/时钟树综合|时钟树综合（CTS）]] — 综合阶段假定时钟理想抵达，CTS 阶段才引入真实的时钟延迟和偏斜；通常预留时钟不确定性（Clock Uncertainty）的 50%-80% 用于补偿后续 CTS 引入的偏斜
- [[asic-flow/concepts/布局布线|布局布线（P&R）]] — 综合输出的门级网表是 P&R 的直接输入，物理综合的目标就是减少综合与 P&R 之间的时序鸿沟；综合的单元分配（Cell Sizing）影响 P&R 的布局密度
- [[asic-flow/concepts/功耗分析|功耗分析（Power Analysis）]] — 门控时钟是综合阶段的核心低功耗技术，门控使能信号的生成逻辑直接影响功耗效率；综合阶段的多 Vth 分配决定漏电-速度的初始折中
- [[asic-flow/concepts/签核|签核（Signoff）]] — 综合后的 LEC 是签核的第一个正式关卡，综合质量直接影响后续所有阶段的收敛难度
- [[asic-flow/concepts/可测试性设计|可测试性设计（DFT）]] — 扫描替换在综合后执行——综合必须为扫描 MUX 留出时序裕度，综合阶段的 DRC 检查需要覆盖 DFT 引入的额外约束
- [[asic-flow/concepts/物理验证|物理验证（Physical Verification）]] — 综合输出的门级网表虽然尚未有版图信息，但门级 DRC（max_transition, max_capacitance）在此阶段就需要满足——这些门级 DRC 违例在后期版图中修复的代价更大
