# 功能验证总览

功能验证（Functional Verification）是数字集成电路开发流程中验证设计功能正确性的关键环节。与制造测试（Manufacturing Test, DFT）关注物理缺陷不同，功能验证专注于回答一个根本问题：**设计的行为是否符合规范（Specification）？** 随着芯片规模从数千门增长到数百亿晶体管，功能验证已经超越 RTL 设计本身，成为数字 IC 项目中占用资源和时间最多的环节——在大型 SoC 项目中，验证工程师与设计工程师的比例通常为 2:1 至 3:1。

本 MOC 汇总功能验证领域的核心概念，涵盖验证方法学（UVM）、断言检查（SVA）、覆盖率驱动验证（CDV）、约束随机激励（CRV）、形式验证（Formal Verification）和验证平台架构（Testbench Architecture）六大方向。

## 核心概念索引

### 验证方法学

- [[verification/concepts/UVM方法学|通用验证方法学（UVM）]] — IEEE 1800.2-2020 标准，工厂模式，Phase 机制，TLM 通信，RAL 寄存器建模。UVM 是当前工业界功能验证的事实标准框架。

### 断言与属性检查

- [[verification/concepts/SVA断言|SystemVerilog 断言（SVA）]] — 即时断言 vs 并发断言，属性（Property）/序列（Sequence），蕴含运算符（`|->` 和 `|=>`），temporal operators（`##`, `[*]`, `[=]`, `[->]`），`$rose`/`$fell`/`$stable`，`bind` 机制。SVA 是协议时序检查的声明式语言。

### 覆盖率驱动的验证

- [[verification/concepts/覆盖率模型|覆盖率模型（Coverage Model）]] — 代码覆盖率（行/翻转/分支/FSM）vs 功能覆盖率，covergroup/coverpoint 语法，bins（auto/显式/illegal/ignore），cross 交叉覆盖，覆盖率驱动验证（CDV）的迭代闭环流程。

### 激励生成

- [[verification/concepts/约束随机验证|约束随机验证（Constrained-Random, CRV）]] — `rand`/`randc` 随机变量，constraint 块，分布约束（`dist`），软约束（soft constraint），内联约束（`with()`），`randomize()` 与 pre/post_randomize 回调，约束求解器基础。

### 形式化方法

- [[verification/concepts/形式验证|形式验证（Formal Verification）]] — 属性检查/模型检查，等价性检查（LEC），有界模型检查（BMC），k-归纳，形式覆盖率（可达性分析），形式验证 vs 仿真的适用场景分工与互补策略。

### 验证基础设施

- [[verification/concepts/验证平台架构|验证平台架构（Testbench Architecture）]] — 分层验证平台（Layered Testbench），Agent（Sequencer/Driver/Monitor），Scoreboard（参考模型 + 比较器），虚拟接口（Virtual Interface），config_db 配置机制，Environment 分层集成，回归测试（Regression）策略与基础设施。

## 相关设计领域

验证与设计是一体两面——验证环境设计需要深入理解被验证设计（DUT）的架构和协议：

- [[rtl-design/RTL设计|RTL 设计总览]] — DUT 的实现基础：Verilog/SystemVerilog 编码规范，FSM 设计范式，流水线（Pipeline）协议，跨时钟域（CDC）同步结构。验证工程师需要能读懂 RTL 以定位 Bug 根因和编写白盒断言。
- [[architecture/体系结构|计算机体系结构总览]] — DUT 的架构基础：流水线级数与数据转发路径，乱序执行与重排序缓冲（ROB），缓存一致性协议（MESI/MOESI），总线协议（AXI/ACE/CHI）。验证工程师需要理解架构规范以编写 Scoreboard 参考模型和覆盖率模型。
- [[asic-flow/ASIC流程|ASIC 实现流程总览]] — 验证与实现流程的交叉点：综合（Synthesis）后的 LEC 等价性检查——形式验证确保网表与 RTL 功能等价；门级仿真（Gate-Level Simulation）——带 SDF 反标时延的后仿，验证关键路径的时序正确性；Signoff 阶段的功耗/时序/物理验证与功能验证的交互。

## 跨领域交叉概念

验证工具和方法论横跨多个领域，以下交叉概念在验证实践中经常被引用：

- [[cross-domain/concepts/跨时钟域设计|跨时钟域（CDC）]] — CDC 验证是形式验证的杀手级应用场景。需要结合 SVA 断言描述跨域协议（如格雷码 FIFO 的指针同步约束），并使用形式工具（JasperGold CDC、Questa CDC）自动检查亚稳态同步结构的正确性。
- [[cross-domain/concepts/时序收敛|时序收敛（Timing Closure）]] — 验证环境（前仿/RTL 仿真）不应依赖具体时序延迟——功能正确性必须在零延迟假设下成立。后仿（Gate-Level Simulation with SDF）中的时序违例需要与 STA（静态时序分析，Static Timing Analysis）结果交叉验证以区分真正的功能 Bug 和时序模型不准确。
- [[cross-domain/concepts/低功耗设计|低功耗设计验证]] — UPF/CPF 驱动的功耗状态机（Power State Table）验证需要特殊的仿真序列（Power-Up/Down Sequence）和断言来检查电源域切换的正确性、隔离单元（Isolation Cell）的行为、状态保持寄存器（Retention Register）的保存/恢复。
- [[cross-domain/concepts/复位策略|复位策略验证]] — 复位（Reset）是验证中最易遗漏的场景之一。复位序列的正确释放时序、复位域交叉（异步复位跨时钟域）、部分复位的局部复位策略，都需要专门的断言和覆盖率检查。形式验证的 X-Propagation 分析可自动检测复位后未初始化的寄存器。

## 基础知识

验证工作涉及的数字IC基础概念位于 `concepts/` 目录：

- [[concepts/CMOS基础|CMOS 基础]] — 理解逻辑门的电气行为（驱动强度、X/Z 状态的物理来源），是 RTL 仿真和门级仿真中调试不定态（X-Optimism/X-Pessimism）问题的基础。
- [[concepts/数制|数字的数制表示]] — 定点/浮点运算在 Scoreboard 参考模型中的数制一致性问题：DUT 使用定点 Q 格式、参考模型使用浮点 double 时，需要显式处理精度截断和饱和行为的对齐。

## 概念关系图

Coverage Model 定义"验证什么"（验证目标），CRV 决定"怎么生成激励"（约束随机激励），SVA 和 Formal 负责"怎么检查"（断言和形式验证），三者通过 Testbench Architecture 集成，UVM Framework 提供标准化实现范式。

## 推荐学习路径

对于刚接触功能验证的学习者，建议按以下顺序阅读：

1. **先理解验证的本质问题**：[[verification/concepts/验证平台架构|验证平台架构]] — 建立 "分层验证平台" 的全局认知框架，理解关注点分离的核心哲学。
2. **掌握验证方法学的工业标准**：[[verification/concepts/UVM方法学|UVM 方法学]] — 理解 Agent、Sequence、Phase、TLM、Factory 等核心概念及其在大型项目中的组织方式。
3. **学习激励生成方法**：[[verification/concepts/约束随机验证|约束随机验证]] — 完成从 "定向测试思维" 到 "约束随机生成 + 覆盖率闭环" 的范式转变。
4. **学习正确性检查方法**：
    - [[verification/concepts/SVA断言|SVA 断言]] — 协议时序的声明式检查，理解如何用属性描述设计意图。
    - [[verification/concepts/覆盖率模型|覆盖率模型]] — 验证充分性的量化度量，理解 CDV 迭代循环。
5. **探索高级验证方法**：[[verification/concepts/形式验证|形式验证]] — 理解数学证明 vs 统计推断的本质差异与应用边界。
6. **回到设计侧建立完整认知**：从 [[rtl-design/RTL设计|RTL 设计]] 阅读设计视角的同一套概念，理解设计者和验证者的不同关切和协作方式。
