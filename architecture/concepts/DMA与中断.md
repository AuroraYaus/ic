# DMA 与中断

DMA（Direct Memory Access，直接存储器访问）和中断（Interrupt）是数字IC系统中两个基础的系统级机制——DMA 负责高效的数据搬运（将处理器从批量数据复制中解放），中断负责异步事件的通知和处理（使处理器能及时响应外部事件）。两者协同工作：DMA 完成数据传输后通过中断通知处理器，形成"硬件搬运 + 软件异步处理"的高效数据流。

## 原理

### DMA 工作原理

DMA（Direct Memory Access）是一种允许外设或存储器之间直接传输数据的硬件机制，无需处理器逐字节介入。在没有 DMA 的传统程序控制IO（Programmed I/O, PIO）模式下，处理器必须执行 Load 指令从源地址读取数据到寄存器，再执行 Store 指令将数据写入目标地址——对于大批量数据（如从 UART 接收缓冲区搬运 1KB 到内存），处理器将消耗数千个时钟周期在单纯的数据复制上，完全无法执行其他任务。DMA 引擎的出现彻底解决了这一问题——处理器仅需配置 DMA 控制器（源地址、目标地址、传输长度和触发条件），DMA 控制器随后自主完成所有数据搬运，处理器在此期间可执行其他程序。DMA 传输完成后通过中断通知处理器——处理器仅在起始配置和结束处理时介入，数据传输期间完全解放。

DMA 控制器（DMAC）的内部结构和工作流程：DMAC 包含多个独立的 DMA 通道，每个通道维护自己的源地址寄存器、目标地址寄存器和传输计数寄存器。处理器通过总线（AHB/AXI）配置这些寄存器后启动 DMA 通道。DMAC 随后作为总线主设备主动发起读写事务——从源设备读取数据到内部 FIFO 缓冲，再从 FIFO 写入目标设备。DMA 传输可以是单次（Single Transfer，传输指定长度后停止）或循环（Circular Transfer，传输到末尾后回绕到起始地址连续传输，常用于音频/视频流缓冲）。DMA 支持多种传输触发源：软件触发（处理器写寄存器启动）、硬件触发（外设 FIFO 满/空信号触发）、链表触发（通过描述符链表实现分散-聚集传输）。

DMA 对系统性能的提升是巨大的。以典型的 1KB UART 接收为例：PIO 模式下每条 Load/Store 指令约处理 4 字节（32 位寄存器），1KB 需 256 次 Load + 256 次 Store = 512 次指令执行——加上中断处理开销和循环跳转，共约 2000-3000 个处理器周期。DMA 模式下处理器仅需约 50-100 个周期配置 DMA 寄存器，数据传输由 DMA 硬件并行完成——处理器节省了 95%+ 的时间用于执行更有价值的计算任务。在 SoC 中，DMA 是数据流的核心基础设施——音频 DSP 通过 DMA 从 I2S 接口接收音频采样流，GPU 通过 DMA 从系统内存传输纹理数据，NVMe SSD 通过 DMA 将数据直接写入内存缓冲区。

- **DMA 将处理器从批量数据复制中解放**：处理器仅需配置（源地址 + 目标地址 + 长度）和响应完成中断——数据传输由 DMA 控制器自主完成，处理器时间节省 95%+
- **DMA 控制器作为总线主设备主动发起事务**：DMA 的 AHB/AXI Master 接口使其能独立读写系统内存和外设寄存器——无需处理器参与数据路径
- **分散-聚集（Scatter-Gather）DMA 是高级模式**：通过内存中的描述符链表指定多个源-目标-长度三元组——单次 DMA 启动可完成不连续内存区域的批量搬运，无需多次中断处理器
- **循环 DMA 是流式数据的标准方案**：传输到末尾自动回绕到起始地址——音频采样流和视频帧缓冲利用循环 DMA 实现连续数据流，零处理器开销
- **DMA 通道优先级和 FIFO 深度设计**：高优先级通道（如显示刷新）获得更多总线仲裁机会，FIFO 深度（通常 8-64 字）决定 DMA 的突发传输效率和反压容忍度
- **Cache 一致性与 DMA 的交互是关键设计难点**：DMA 写入内存的数据可能使处理器缓存中的对应行过期——需要 Cache 维护操作（Clean/Invalidate）确保处理器和 DMA 看到的数据一致
- **DMA 数据宽度匹配**：DMA 源和目标的数据宽度可能不同（如 32 位 FIFO 到 64 位内存）——DMA 控制器内置数据宽度转换和打包/解包逻辑

### 中断（Interrupt）基本流程

中断（Interrupt）是硬件向处理器发出的异步信号，通知处理器发生了需要立即处理的事件——外部设备到达了新数据（UART 接收完成、GPIO 引脚电平变化）、定时器到期（系统 tick、看门狗）、错误事件（总线错误、奇偶校验错误）。中断机制使处理器能从"轮询"（Polling）的低效等待模式中解放——轮询模式下处理器定期检查外设状态寄存器，每次检查消耗数十到数百个周期且大部分检查结果为空（无事件），浪费了大量处理器时间。中断模式下处理器正常执行程序流（前台程序），中断事件发生后硬件暂停当前程序流、保存上下文、跳转到中断服务程序（Interrupt Service Routine, ISR）处理事件，处理完毕后恢复上下文继续原程序——"异步响应、按需处理"。

中断的基本处理流程：当一个外设或内部模块产生中断请求（IRQ）时，中断信号首先到达中断控制器（Generic Interrupt Controller, GIC）。GIC 是多核 SoC 中的标准中断管理基础设施——它接收所有外设和核间中断源（SPI, Shared Peripheral Interrupt 共享外设中断；PPI, Private Peripheral Interrupt 私有外设中断如每个核心的定时器；SGI, Software Generated Interrupt 软件产生中断用于核间通信）。GIC 根据每个中断的优先级和当前核心的中断屏蔽状态（Priority Mask），选择一个最高优先级的中断并将其转发到目标核心。目标核心在当前指令执行完毕后（精确异常点，Precise Exception Point）采样中断信号——如果满足响应条件（中断使能、优先级高于当前执行等级），处理器进入中断异常处理流程：硬件自动保存关键上下文（如 AArch64 中 PSTATE 和返回地址保存到 SPSR_EL1 和 ELR_EL1），将处理器异常等级切换到对应的 Exception Level（EL1/EL2/EL3），跳转到异常向量表中对应的中断处理入口。ISR 执行中断服务逻辑后通过写 GIC 的 End of Interrupt（EOI）寄存器通知 GIC 中断处理完成（或在 ISR 返回时隐式完成）。中断处理的延迟来源包括：中断采样同步延迟（1-2 周期）、总线接口延迟（GIC 访问延迟）、上下文保存硬件开销（3-10 周期）和 ISR 的指令缓存预热开销。

中断系统的关键设计参数：中断延迟（Interrupt Latency）——从中断信号产生到 ISR 第一条指令执行的时间，硬实时系统要求通常在 10-20 个周期以内；中断优先级（Interrupt Priority）——GICv3/v4 支持最多 256 个优先级（ARM 中高数值 = 高优先级），嵌套中断（Nested Interrupt）允许高优先级中断抢占正在执行的低优先级 ISR；中断亲和性（Interrupt Affinity）——在多核系统中，每个中断可配置路由到特定核心或一组核心，用于负载均衡和实时核心隔离；尾链中断（Tail-Chaining）——当一个 ISR 完成时有另一个挂起中断，处理器跳过完整的上下文保存/恢复，直接切换到下一个 ISR（ARM Cortex-M 支持此特性，节省约 6-8 个周期）。

- **中断替代轮询节省处理器时间**：轮询浪费周期在空检查上——中断按需触发，处理器仅在事件发生时介入，将 CPU 利用率从可能低于 1% 提升至近 100%
- **GIC 是 SoC 中断管理的核心基础设施**：管理数百个外设中断源（SPI）、每核心私有中断（PPI）和核间中断（SGI）——根据优先级和核心屏蔽状态选择并将中断路由到目标核心
- **中断向量表入口由异常类型决定**：AArch64 的异常向量表有 16 个入口（4 种异常类型 × 4 种异常等级组合），中断（IRQ）对应固定偏移——硬件直接跳转到向量表中对应入口
- **中断优先级和抢占避免优先级反转**：高优先级中断可抢占低优先级 ISR——实时任务的中断优先级设置（如电机控制中断 > 网络中断）是系统实时性的关键配置
- **中断延迟由多因素构成**：中断同步延迟 + GIC 访问延迟 + 上下文保存 + ISR 指令缓存预热——硬实时系统需将此总延迟控制在 10-20 个周期以内
- **中断和 DMA 的协同是最佳实践**：DMA 完成批量数据传输后触发中断通知处理器——处理器在 DMA 传输期间完全释放，仅在传输完成时接收一次中断
- **MSI（Message Signaled Interrupt）是 PCIe 中断的标准方式**：通过总线写事务而非专用中断线发送中断——解决了传统 INTx 中断的引脚数量和共享问题

## 关键要点

- **DMA 三大要素**：源地址 + 目标地址 + 传输长度——处理器一次性配置，DMA 控制器自主完成数据传输
- **DMA 和 Cache 一致性需要维护操作**：DMA 写内存前 Clean 缓存（保证 DMA 读到最新数据），DMA 写内存后 Invalidate 缓存（保证处理器读到 DMA 新写入数据）
- **分散-聚集 DMA 实现零拷贝数据流**：不连续内存区域通过描述符链表一次性传输——网络协议栈和文件系统是利用分散-聚集 DMA 的典型案例
- **中断嵌套保证实时性**：高优先级中断抢占低优先级 ISR——嵌套深度通常限制在 2-3 层以防止栈溢出
- **GICv3 支持最多 256 个优先级 + 亲和性路由**：中断可按需路由到特定核心或通过负载均衡算法分发——实时系统通常将高优先级中断固定到专用核心
- **DMA + 中断组合形成异步数据流**：DMA 搬运数据 → 完成中断触发 ISR → ISR 处理数据并重新配置 DMA → 循环——处理器仅介入场景边界而非数据传输路径
- **中断屏蔽防止临界区被打断**：处理器在执行不可重入代码段时通过优先级屏蔽（Priority Mask）禁用等于或低于某优先级的中断——保护共享数据的原子性
