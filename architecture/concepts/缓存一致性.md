# 缓存一致性

在多核处理器系统中，每个核心拥有独立的私有缓存（L1 和通常 L2），多个核心可能同时缓存同一内存地址的数据副本。缓存一致性协议（Cache Coherence Protocol）确保所有核心对任何内存地址的读操作都返回该地址的最新写入值——即维护单写多读（Single-Writer, Multiple-Reader, SWMR）不变性，确保没有两个核心同时拥有一个地址的可写（脏/独占, Dirty/Exclusive）副本。一致性协议与内存一致性模型共同规范了多核共享内存的语义。

## 原理

### 一致性的定义与不变量

缓存一致性的严格定义由两个不变量构成：（1）单写多读不变量——在任何时刻，对于一个给定的内存地址，至多一个核心可以拥有其可写副本（即可以写入该地址），零个或多个核心可以拥有其只读副本；（2）数据值不变量——在任何时刻，一个给定地址的数据值在所有副本中保持一致；当一个核心写入一个新值时，任何后续对该地址的读取必须返回该新值（或后续写入的更新的值）。一致性协议通过状态机模型来维护这两个不变量。每个缓存行在给定核心的本地缓存中处于一个状态，状态转换由本地处理器操作（Load/Store）和远程一致性消息（如来自其他核心或目录的请求）触发。

### MSI 到 MESI 到 MOESI 协议演进

MSI 协议（Modified / Shared / Invalid）是最基本的侦听式一致性协议。Modified 状态表示缓存行被修改过（脏），该核心拥有唯一有效副本且内存数据已过期；Shared 状态表示缓存行干净且可能被一或多个核心共享；Invalid 状态表示缓存行无效。MSI 协议的核心缺陷是缺少 Exclusive 状态——即核心读取一个不被任何其他核心持有的缓存行时仍然需要广播，且随后的写入还需要再广播一次。

MESI 协议（Modified / Exclusive / Shared / Invalid）引入了 Exclusive（E）状态作为关键优化。当一个核心读取缓存行且该行未被其它核心持有时，进入 E 状态而非 S 状态。E 状态表示该缓存行干净（与内存一致）且该核心是唯一持有者。当该核心稍后执行 Store 时，可以从 E 静默升级为 M 状态——不需要任何总线事务，因为已经知道自己是唯一持有者。在程序中，数据通常被读取后很快被修改（读-修改-写模式），MESI 消除了约 20-30% 的总线带宽开销。

MOESI 协议（Modified / Owned / Exclusive / Shared / Invalid）进一步引入了 Owned（O）状态。场景：核心 A 拥有 M 状态脏缓存行，核心 B 请求读取该行。在 MESI 中，A 必须回退到 S 并同时写回数据到内存；在 MOESI 中，A 进入 O 状态——它仍是脏数据的"所有者"负责最终写回，但此时数据与 B 共享（B 为 S）。O 状态避免了不必要的写回：若该缓存行之后被 A 修改，可从 O 直接升级为 M；若被其他核心读取，由 O 核心直接提供数据而不需要访问内存。MOESI 在 AMD 处理器和部分 ARM 实现中广泛采用。

### 侦听式协议

侦听式一致性协议利用共享总线的广播特性实现一致性。所有核心的缓存控制器持续监控总线上的所有事务，根据事务类型（BusRd / BusRdX / BusUpgr / Flush / WB）和自身缓存的状态按照状态转换表执行状态机转换。共享总线的事务顺序天然提供了一致性事务的全局串行化——但这也是可扩展性的根本限制：总线是单点瓶颈，随着核心数增加事务数超线性增长。侦听协议可扩展到约 8-16 个核心，之后总线饱和。

### 目录式协议

目录式一致性协议通过在内存端维护分布式目录来跟踪每个缓存行的共享者集合，避免广播。每个缓存行在目录中有一个条目，记录全局状态和共享者位向量（每一位代表一个核心）。操作流程：核心请求缓存行时向归属节点发送请求消息，归属节点查询目录决定是直接提供数据、向脏数据持有者转发请求、还是向共享者广播无效化消息。目录式协议支持数百个核心的系统，代价是位向量存储开销随核心数 O(N) 增长。解决方案包括有限指针（保持 3-4 个共享者，超过后广播）和粗粒度向量（每几位代表一个核心簇）。

### 伪共享

伪共享发生在两个以上核心访问同一缓存行中的不同数据时——尽管在程序语义上它们是独立变量。由于一致性协议以缓存行（通常 64 字节）为粒度，当一个核心写入时，其他核心的副本必须失效。伪共享导致乒乓效应——缓存行在核心间来回迁移，每次伴随无效化消息和缓存缺失延迟。消除技术包括数据结构填充（Padding，如在关键变量前后插入 64 字节填充数组使变量独占缓存行）、线程本地存储，以及按线程分区数据结构。

### 内存一致性模型

缓存一致性协议保证了对单一地址的写入在所有核心看来有一致的全局顺序。内存一致性模型进一步规范了对多个不同地址的操作在多核之间的可见性排序约束。TSO（Total Store Order）是 x86 处理器采用的一致性模型：所有核心看到所有 Store 的全局总顺序；同一核心的 Load 不能被后发的 Store 绕过（Load-Store 顺序保持），但 Store 可被后发 Load 绕过（Store-Load 可重排，Store Buffer 效应）。x86 提供 MFENCE 指令建立 Store-Load 屏障。

弱排序（Weak Ordering / Release Consistency）是 ARM 和 RISC-V 采用的一致性模型。默认硬件可对几乎所有类型访存进行重排序（包括 Load-Load、Store-Store、Load-Store、Store-Load 间任意重排）。程序通过 Acquire 语义（Load Acquire）和 Release 语义（Store Release）或显式 Fence 指令（RISC-V 的 FENCE 指令）向硬件明确要求排序约束。弱排序给予了微架构最大的优化自由度，代价是程序员必须显式标注同步点。

### 一致性协议的实现考量

现代高性能处理器的一致性协议实现是一个多层协同系统。私有 L1/L2 缓存通过 MESI/MOESI 状态机维护，状态转换由本地 Load/Store 和来自末级缓存切片的侦听请求触发。末级缓存作为分布式目录和序列化点——每个切片管理其地址范围的目录条目。一致性请求首先路由到目标地址对应的 LLC 切片，由该切片查询目录并决定是提供数据、转发到脏持有者、还是向共享者广播无效化。

Snoop Filter 是性能关键部件。它为每个核心簇维护私有缓存内容的高度压缩摘要（Bloom Filter 或部分标签），用于过滤不必要的侦听。没有 Snoop Filter 时，每次 LLC 缺失都需要广播到所有核心——即使某核心根本没有缓存该地址，导致私有缓存标签阵列被一致性流量过度占用。Snoop Filter 的压缩率和假阳性率的权衡是其设计难点。当 Snoop Filter 因假阳性发出不必要的侦听时，收到侦听的核心进行标签比较后返回"无此缓存行"响应——这额外消耗了侦听带宽但未产生数据迁移。

### 一致性协议的性能分析

一致性协议的性能瓶颈表现为一致性缺失（Coherence Miss）的延迟。一次典型的目录协议一致性缺失的延迟分解为：请求方到归属节点的网络延迟（Request Latency）→ 目录查询延迟（Directory Lookup，通常 3-5 个周期）→ 向脏数据持有者或共享者发送侦听消息的网络延迟（Snoop Latency）→ 数据持有者回复数据的网络延迟（Data Response Latency）。在大型 NUMA 系统中，远程访问的总延迟可达数百个周期，其中大部分为网络跳数延迟。

"写升级"（Write Upgrade）模式在生产者-消费者场景中体现了一致性开销。生产者写入 → 使所有共享者失效（Invalidation）→ 消费者读取 → 从生产者获取脏数据 → 消费者写入 → 使生产者失效。如果生产者和消费者轮流访问，每一轮都触发两次一致性迁移——这就是经典的生产者-消费者乒乓。解决方案是使用基于无锁数据结构的设计模式（如 Ring Buffer with Head/Tail 指针分离），减少写入者间的直接竞争。

### 目录协议的变体与存储优化

目录的存储开销随核心数线性增长，是目录式协议可扩展性的主要瓶颈。全位向量目录（Full Bit-Vector Directory）为每个核心分配 1 位，N 核系统每个目录条目需 N 位。当 N=1024 时，每个 64 字节缓存行的目录条目为 1024 位 + 状态位（128 字节），目录的存储开销超过了数据本身的存储开销。三种经典优化方案：（1）有限指针目录（Limited Pointer Directory）——仅存储 K 个共享者指针（通常 K=3-4），超过 K 个共享者时退化至广播模式。此方案基于观察：绝大多数缓存行在任一时刻的共享者数量不超过 2-3 个。（2）粗粒度位向量目录（Coarse-Grain Bit-Vector Directory）——每位代表一个核心簇（通常 4-8 个核心），位宽减少 4-8 倍，代价是簇内广播的额外侦听开销。（3）稀疏目录（Sparse Directory / Directory Cache）——仅缓存活跃共享的缓存行目录条目，通过 SRAM 目录缓存保存最近访问的一小部分目录状态，类似小型全相联缓存。缺失时回退到内存中的完整目录表或广播。

### 一致性协议的验证与形式化方法

缓存一致性协议的正确性直接关系到多核系统的功能正确性，其状态空间（状态数 × 核心数 × 地址数 × 事务类型数）的组合爆炸使人工验证极容易出错。工业实践中，一致性协议的验证采用分层方法：在事务级，使用模型检验工具（如 Murphi / TLA+）对所有可能状态转换进行穷举验证，检查不变量（SWMR、数据值、无死锁）在所有可达状态下是否成立。在实现级，RTL 验证通过 SystemVerilog 断言（SVA）在仿真和形式验证中检查关键协议属性——如"一个缓存行不能同时在两个核心的 Modified 状态"。Synopsys 的 Verdi Protocol Analyzer 和 Cadence 的 JasperGold 专门针对一致性协议提供自动验证检查。ARM 的 CHI 规范提供了形式化参考模型（FRM）作为一致性协议的黄金标准。

### 缓存一致性与 MESI 协议各状态

在多核处理器系统中，每个核心拥有独立的私有缓存（L1 和通常 L2），多个核心可能同时缓存同一内存地址的数据副本。缓存一致性协议（Cache Coherence Protocol）确保所有核心对任何内存地址的读操作都返回该地址的最新写入值——即维护单写多读不变量（Single-Writer, Multiple-Reader, SWMR）：在任何时刻，对于任一内存地址，至多一个核心可拥有其可写副本（即可修改该地址的值），但零个或多个核心可拥有其只读副本。如果两个核心同时拥有同一地址的可写副本，它们可能各自写入不同值——后续读取将取决于哪个核心先读，程序行为变得不确定且不可重现。缓存一致性协议通过状态机模型严格约束每个核心的缓存行状态转换来保证 SWMR 不变量。

MESI 协议（Modified / Exclusive / Shared / Invalid）是工业界最广泛采用的一致性协议，定义了缓存行的四种状态：(1) Modified（M, 已修改）——缓存行被修改过（脏数据），该核心拥有唯一有效副本，内存中的对应数据已过期。该核心可读写此缓存行而无需任何总线事务。当其他核心请求该缓存行时，M 状态核心必须提供数据（或回写到内存），因为它是唯一拥有最新数据的核心。(2) Exclusive（E, 独占干净）——缓存行与内存一致（干净数据），该核心是唯一持有者——其他核心可能没有此缓存行的有效副本。该核心可静默升级为 Modified 状态（从 E 到 M 零总线事务），因为已知自己是唯一的持有者——这节省了一次总线事务（如果是 Shared 状态则需要 Invalidate 总线广播）。(3) Shared（S, 共享干净）——缓存行与内存一致（干净数据），可能被多个核心同时持有共享副本。该核心可读取此缓存行但修改前必须将其他核心的共享副本作废（通过 Invalidate 总线事务升级至 M 状态随后写入）。(4) Invalid（I, 无效）——缓存行不存在于缓存中（或已被作废）。访问此地址将导致缓存缺失——读取缺失触发总线读取事务，写入缺失触发"读取 + 意图修改"事务（BusRdX 或 Read With Intent to Modify）将数据取回并独占该行。

MESI 协议的状态转换由本地处理器操作和外总线事务共同驱动。关键的状态转换路径：(1) 读取未缓存的地址 → I 到 E（如果没有其他核心共享该行）或 I 到 S（如果有其他核心共享该行）。E 的获取需通过总线窥听机制确认无其他核心持有有效副本。(2) 写入 M 或 E 状态的缓存行 → 无需总线事务，静默修改（E 先转换至 M）。这是 MESI 相对于 MSI 协议的关键优化——MSI 中即使是独占持有者的写入仍需广播总线事务通知不存在其他持有者。(3) 写入 S 状态的缓存行 → 需先广播 Invalidate 总线事务（BusUpgr）使其他核心的副本作废，再升级至 M 并写入。(4) 其他核心请求 M 状态缓存行（BusRdX）→ M 核心必须提供脏数据（写回内存或直接提供给请求核心）并将自身状态从 M 降至 I（或 S，取决于实现）。从 M 降级到 I 或 S 的单次操作称为"脏驱逐"或"干预"。(5) 其他核心读取 S 或 E 状态的缓存行（BusRd）→ S 或 E 核心保持 S 状态（如果是 S 则仍在共享集中，如果是 E 则变为 S——共享者数量增加）。

MESI 中的 Exclusive 状态是相对于 MSI 协议最关键的创新。在程序行为中，数据被读取后通常很快被修改（读-修改-写模式）——例如循环计数器的递增。在 MSI 中，读取未共享行进入 S 状态以后修改时需总线事务（Broadcast Invalidate）再升级到 M 状态；在 MESI 中，同一场景进入 E 状态后可以静默升级到 M——节省了一次总线事务。根据实测，MESI 的 E 状态消除了约 20-30% 的总线事务——这是 MESI 取代 MSI 成为工业标准一致性协议的根本原因。

## 关键要点

- **MESI Exclusive 状态优化读后写**：从 E 到 M 零总线事务，在读密集且写也密集的代码中效果显著
- **MOESI Owned 状态解决共享脏数据**：由 O 核心直接提供数据，避免所有读取者访问 DRAM
- **侦听协议扩展上限 ~16 核**：之后共享总线带宽和 Snoop Filter 延迟成为瓶颈
- **目录位向量存储开销 O(N)**：对 1024 核系统，简单位向量占缓存行的两倍，是主要限制
- **目录协议三级跳延迟更长**：请求方-归属节点-脏持有者-请求方比侦听协议两跳更长，需额外缓存容忍
- **伪共享检测工具 perf c2c**：Linux `perf c2c` 通过采样 L2/L3 一致性缺失来定位伪共享热点
- **TSO 通过 Store Buffer 实现**：Store Buffer 合并写入 + 按序提交——提交顺序决定 Store 全局可见顺序
- **RISC-V FENCE 细粒度屏障**：RISC-V RVWMO 通过 FENCE 指令提供与 x86 MFENCE 等效的细粒度可控屏障
- **有限指针目录降存储开销**：利用共享者数通常 ≤2-3 的观察，将存储开销从 O(N) 降至 O(K)，覆盖 99%+ 的共享模式
- **全位向量目录致命缺陷**：在 1024 核系统中每个缓存行的目录存储开销（1024 位 = 128 字节）超过数据行本身（64 字节）
- **形式化验证是流片关口**：一致性协议的形式化验证（TLA+/Murphi）是 SoC 流片前的强制性质量关口——协议级缺陷在硅后无法修复
- **CHI 形式化参考模型**：ARM CHI FRM 通过穷举可达状态空间检查 SWMR 不变量和无死锁属性，是目录式协议验证的工业标准
- **一致性缺失三级延迟分解**：请求→目录→脏持有者→请求方，在 64+ 核 NUMA 系统中可达 200-500 周期，网络跳数主导了延迟
- **CHI 信用流控消除瓶颈**：为每条虚通道预分配发送信用，接收方返回信用令牌，消除 AXI READY Handshake 在长物理链路上的流量控制瓶颈
- **协议死锁避免策略**：Request 和 Response 消息必须使用独立的虚网络，否则请求等待响应、响应等待数据、数据等待缓冲释放的循环将导致协议级死锁
- **Snoop Filter 容量管理**：溢出时需回退至全广播模式——此时性能退化但功能正确性不变，Bloom Filter 型压缩率高但存在假阳性代价
- **无效化 vs 更新方案**：无效化产生一致性缺失但数据仅需传输一次，更新在写入时广播新值但占用高带宽——现代协议几乎全采用无效化方案
- **自修改代码一致性挑战**：指令缓存和数据缓存必须保持一致性——通过 I/D 一致性操作（IC IVAU / DC CVAU）或硬件侦听建立同步点
