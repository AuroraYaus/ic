# Wavedrom 绘制规则

**Wavedrom** 是一个用 JSON 文本（WaveJSON）描述数字波形时序图的开源绘图工具：每根信号的波形用一串字符表示——**每个字符对应一个时钟周期**——由浏览器端 JS 引擎渲染成 SVG。知识库中波形图/时序图一律走 Wavedrom（`.json` → `.html` → `.svg` 三件套，见 [[CLAUDE|CLAUDE.md]] 图表规范），电路图/架构图才用 Mermaid。两者的分工是：Wavedrom 描述"信号随时间变化的电平序列"（周期语义），Mermaid 描述"节点与连接关系"（拓扑语义）。

## 基础结构

最小 WaveJSON 由 `signal` 数组组成，每项描述一根信号：

```json
// 注释仅为教学示意——JSON 文件本身不支持注释
{
  "signal": [
    {"name": "clk", "wave": "p...."},       // p 生成方波时钟，其后 4 个点重复 4 拍
    {"name": "data", "wave": "1.0.x"}       // 高、保持高、低、保持低、未知
  ],
  "config": {"hscale": 2}                   // 水平缩放系数：2 = 每字符 80px（本库惯例）
}
```

关键字段：

- `name`：信号名，渲染在波形左侧
- `wave`：波形串——每字符一个时钟周期，是本格式的核心
- `head` / `foot`：图标题 / 图注——foot 用于标注关键时间点的语义（如"t=7 释放沿与 clk 沿重合"）
- `data`：标签数组，按出现顺序与波形串中的带数据字符（`2`/`3`）配对
- `config.hscale`：水平缩放系数，值越大每字符占宽越宽

## 字符总表

| 字符 | 语义 | 渲染 | 适用场景 |
|:---|:---|:---|:---|
| `0` | 低电平 | 底边线 | 单比特信号 |
| `1` | 高电平 | 顶边线 | 单比特信号 |
| `.` | 重复前一字符 | 连续线 | 通用（电平不变就用它） |
| `x` | 未知/亚稳态 | 满幅交叉影线 | 亚稳态窗口、X 传播 |
| `z` | 三态 | 中线 | 三态总线释放 |
| `p` / `n` | 正/负沿时钟 | 方波 | 时钟信号 |
| `u` / `d` | 上升/下降边沿 | 边沿线 | 边沿片段 |
| `2` | 低电平 + 数据标签 | 底线 + 数据框 | 单比特标注（如"断言"） |
| `3` | 高电平 + 数据标签 | 顶线 + 数据框 | 单比特标注（如"释放"） |
| `4` / `5` | 低/高电平 + 箭头 | 电平 + 箭头 | 强调跳变方向 |
| `=` / 数字 | 总线值字符 | 值线 + 数据框 | 总线 lane 标注值 |

## 五条绘制规则

### 规则一：连续同电平必须用 `.` 重复

显式重复同电平字符（`0000`、`1111`）不会渲染成一条连续直线——Wavedrom 在**每个周期边界**画一个小尖刻（0m0/1m1 图元），波形呈锯齿状：

```json
{"name": "bad",  "wave": "1000000x1111"}    // ❌ 每两个显式 0 之间一个尖刻
{"name": "good", "wave": "10.....x1..."}    // ✅ 电平不变用 . 重复，只有变化才写新字符
```

`.` 的语义是"重复前一字符"——因此**电平变化处必须写显式字符**（包括 `x` 之后变回 `1` 也要先写一个 `1` 再续 `.`）。这是 Wavedrom 最常见的视觉错误来源，本库曾因整张图布满尖刻而重绘。

### 规则二：data 标签只能挂 `2` / `3`

`data` 数组按出现顺序与波形串中的 `2`/`3` 字符配对。挂标签必须选对字符：`2` = 低电平带标签（标注"断言"类），`3` = 高电平带标签（标注"释放"类）。`x` 与 `=` 上**不渲染标签**——标签会静默丢失，或落在错误电平上。

```json
{"name": "ext_rst_n", "wave": "1020...1....", "data": ["异步断言（立即生效）"]}
//                             ^ '2'：低电平段挂标签——标签与电平一致
```

错误案例：曾用 `3` 给复位断言挂标签——`3` 渲染高电平，图上出现"断言期间复位却为高"的假脉冲，标签语义与波形电平直接矛盾。

### 规则三：`=` 是总线值字符，单比特信号禁用

`=` 与数字是**总线值字符**（多比特 bus 每个周期标注值），用在单比特信号上会渲染成高电平带数据框。曾用它画异步 FIFO 的 rempty 撤销（`1....=......`）——渲染出的波形**根本不下降**，标签写"撤销"而线纹丝不动。单比特标志的撤销要用 `2`（低电平带标签）。

### 规则四：data 字符后的 `.` 会连数据框一起重复

`.` 重复的是"完整上一拍"——包括 `2`/`3` 的数据框。`"2...."` 会把数据框拖满整个同电平段。数据框之后要先写一个**显式电平字符**终止数据框，再继续用 `.`：

```json
{"name": "rempty", "wave": "1....20.....", "data": ["保守撤销：滞后 2 拍"]}
//                             ^ '2' 数据框只占 t5 一拍；显式 '0' 之后 . 才渲染干净低线
```

### 规则五：`.json` 是唯一事实源，改完必须重渲染

`assets/` 下的 `.json`/`.html`/`.svg` 三件套中，`.json` 是唯一事实源。改完 JSON 必须重跑 `tools/render_wavedrom.sh <xxx.json>` 重新生成 `.html` 与 `.svg`（chrome headless + 本地 wavedrom 2.6.8 渲染链路），否则 SVG 与源文件版本漂移。生成后还应解析 SVG 验证每根 lane 的电平序列与字符数（无尖刻图元、各 lane 拍数一致）——本库曾交付过陈旧 SVG 与"12 拍 JSON 渲染出 13 拍波形"的错位图。

## 信号间箭头（edge）与跳线（jump）

`edge` 数组在信号之间画带箭头的因果连线（如握手时序的 req→ack 对应关系）：

```json
{
  "signal": [
    {"name": "req", "wave": "1...........", "node": "A..........."},
    {"name": "ack", "wave": "0.1.........", "node": "..B........."}
  ],
  "edge": ["A->B 握手"],            // 从 A 事件画箭头到 B 事件，标签"握手"
  "config": {"hscale": 2}
}
```

三条语义（渲染器源码实证）：

1. **端点引用 `node` 字符串的事件字符**：signal 项可带 `node` 字段——与 `wave` 等长的标记串，其中每个非 `.` 字符注册一个事件点。edge 字符串的格式是"起点字符 + 形状 + 终点字符"。事件字符还区分大小写：**小写字符在该位置渲染出字符标签**（天然标注点），**大写字符是隐形标记**（不渲染标签、不干扰波形）；同名事件字符多次出现时以后出现者为准，应保持全图唯一。
2. **形状字符**：

| 形状 | 渲染 | 用途 |
|:---|:---|:---|
| `-` | 直线 | 相邻 lane 直连 |
| `~` / `-~` / `~-` | S 曲线（跳线） | 跨越多根中间 lane 时视觉绕过——`-~>` 最常用：起点留缺口避开本 lane 波形、曲线越过中间 lane、箭头落在终点 |
| `-|` / `|-` / `-|-` | 直角折线 | 强调先横后竖/先竖后横的时序关系 |
| `>` / `<` | 箭头 | `->` `<-` `<->` `-~>` `-|>` 等组合，表达因果方向 |

3. **标签**：edge 字符串第一个词（形状词）之后的内容整体作为标签，渲染在连线中点。

跳线（jump）即 `~` 系列形状：连线需要跨过多根中间 lane 时，S 曲线视觉上"跳过"它们而不与波形线相交。注意 edge 引用的是 `node` 字符而非 lane 名——`node` 缺省时事件不存在，edge 静默不渲染。

## 完整示例：复位同步器时序

异步断言、同步释放的复位同步器（完整原理见 [[cross-domain/concepts/复位策略|复位策略]]）是五条规则的集中示范：

```json
{
  "signal": [
    {"name": "clk",       "wave": "p..........."},
    {"name": "ext_rst_n", "wave": "1020...1....", "data": ["异步断言（立即生效）"]},
    {"name": "q1",        "wave": "10.....x1..."},
    {"name": "sync_rst_n", "wave": "10.......31.", "data": ["同步释放（干净边沿）"]}
  ],
  "head": {"text": "复位同步器——异步断言、同步释放（Asynchronous Assert, Synchronous Deassert）"},
  "foot": {"text": "t=1 异步断言 | t=7 释放沿与 clk 沿重合 → 恢复/移除违例 | t=7 段 q1 亚稳态窗口（x）| t=9 sync_rst_n 同步释放"},
  "config": {"hscale": 2}
}
```

对照五条规则：（1）四根信号的电平保持段全部用 `.`；（2）"异步断言"挂在 `2`（低电平段）、"同步释放"挂在 `3`（高电平段）；（3）q1 的亚稳态窗口用 `x` 段（t7），不挂标签——窗口语义写进 foot；（4）ext 的 `2` 之后显式写 `0` 终止数据框，框只占 t2 一拍；（5）四根 lane 均为 12 拍、一一对齐。渲染产物即 `cross-domain/concepts/assets/reset-synchronizer-timing.svg`。

## 三件套渲染工作流

```shell
bash tools/render_wavedrom.sh cross-domain/concepts/assets/reset-synchronizer-timing.json
# 输出：同目录 .html（CDN 引用，浏览器可直接打开）+ .svg（Obsidian 引用）
# 内部链路：本地 wavedrom 2.6.8（缓存于 ~/.cache/wavedrom-2.6.8）
#          + chrome headless --dump-dom 渲染 → 提取 svgcontent_0 → XML 良构校验
```

验证方法：解析生成的 SVG，逐 lane 还原电平序列，核对（1）各 lane 字符数与 JSON 一致；（2）无 0m0/1m1 尖刻图元；（3）数据框只出现在 `2`/`3` 所在拍。

## 关键要点

- **每字符一个时钟周期**：波形串长度即拍数，所有 lane 长度一致才能逐拍对齐——长度不一致是最隐蔽的错误
- **`.` 只用于电平不变的连续段**：显式重复同电平字符会在周期边界渲染尖刻（0m0/1m1 图元），电平变化处必须写显式字符
- **data 标签挂 `2`（低）/`3`（高）**：`x` 与 `=` 上不渲染标签——标签电平必须与语义一致（断言挂低、释放挂高）
- **`=` 是总线值字符**：单比特标志信号禁用——画"撤销"要用 `2`，否则波形根本不下降
- **数据框会随 `.` 扩散**：`2`/`3` 之后先写显式电平字符终止数据框（`...20...`），再继续用 `.`
- **亚稳态窗口用 `x` 段**：交叉影线直观表达恢复/移除违例窗口，语义解释写进 foot
- **`.json` 是唯一事实源**：改完必跑 `tools/render_wavedrom.sh` 重渲染三件套，并解码 SVG 验证电平序列
- **Wavedrom 与 Mermaid 分工**：波形图/时序图走 Wavedrom（周期语义），电路图/架构图走 Mermaid（拓扑语义）
- **edge 端点引用 `node` 字符串的事件字符**：`node` 与 `wave` 等长的标记串，非 `.` 字符注册事件点；`~` 系列形状是跳线（S 曲线越过中间 lane），`-~>` 是标准跳线箭头；小写事件字符渲染标签、大写隐形；node 缺省时 edge 静默不渲染
